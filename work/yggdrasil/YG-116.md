## As
Usuário logado explorando o corpus que quer o Caderno (★/✎/progresso) persistido no servidor.

## I Need
Ligar o `corpus.js` de exploração (329 linhas, YG-111) aos endpoints de Caderno do servidor
(YG-112: `GET/PUT/DELETE /api/v1/comunicacao/caderno/*` + `POST .../migrar`) — ler/gravar no
servidor quando logado, com fallback `localStorage` anônimo e migração no primeiro login.

## So That
O Caderno fica durável/cross-device e suas notas federam (YG-114), fechando o round-trip que o
backend já suporta.

## Context
A wave Phase-2 (2026-06-08) mergeou o **backend** do Caderno (YG-112: `CadernoStore`, rotas,
caderno.rs, federação YG-114) e a **superfície** de exploração (YG-111, `corpus.js` local-first).
O agente de YG-112 reescreveu um `corpus.js` só-Caderno (167 linhas) que foi **descartado** na
reconciliação para preservar a UI de exploração — restam ~6 chamadas `fetch` ao Caderno servidor
a portar para o `corpus.js` real. Trabalho puramente frontend (JS), não coberto por `cargo test`
— requer teste manual/e2e da sincronização logado↔anônimo.

## Acceptance
- **GIVEN** usuário logado  **WHEN** favorita/anota/avança um verso  **THEN** `corpus.js` grava
  via `/api/v1/comunicacao/caderno/*` (JWT); recarregar em outro device recupera.
- **GIVEN** usuário com Caderno local  **WHEN** loga  **THEN** `corpus.js` chama `.../migrar`.
- **GIVEN** anônimo  **THEN** mantém o fallback `localStorage` (sem regressão da UI atual).

## Dependencies
- YG-111 (superfície) ✅ · YG-112 (backend Caderno) ✅. Só falta o wiring do cliente.
