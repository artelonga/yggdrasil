GIVEN o repo `artelonga/universe` já tem cliente Godot 4 + protobuf,
WHEN exponho `GET /api/v1/lobby.proto` (binary) e `WS /api/v1/sessions/<id>`
(stream binary), e adapto o cliente Godot para consumir esses endpoints,
THEN o mesmo lobby visto no canvas web pode ser explorado em 3D no cliente Godot.

Esta é a tarefa-vitrine de **caminho para universos 3D** prometido nos
tiers de recompensa (Tronco, Yggdrasil).

## Referência

- `artelonga/universe` repo — cliente Godot.
- `co/core/proto/` — definições proto existentes.
- `co/co-web/src/game_routes.rs` — login/JWT que o Godot client já consome.

## Critérios de aceitação

- [ ] Adicionar `prost` + `prost-build` em `yggdrasil-web` (dep já presente no game-core).
- [ ] `proto/yggdrasil.proto` com mensagens `Universe`, `Tile`, `Portal`, `Session`.
- [ ] `GET /api/v1/lobby.proto` retorna binary protobuf do mesmo lobby de `/api/v1/lobby` (JSON).
- [ ] WebSocket `/api/v1/sessions/<id>` faz streaming de `tick` deltas para o cliente.
- [ ] Documentar no `docs/GODOT_BRIDGE.md` como rodar o cliente Godot apontando para um servidor Yggdrasil local.
- [ ] Mínimo de demo: cliente Godot mostra os 4 portais como caixas 3D, click teleporta.
