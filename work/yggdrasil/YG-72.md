## As

A platform que se posiciona como "catálogo de RPGs brasileiros open-source"

## I Need

Os ~40 sistemas listados em `docs/RPGs Brasileiros.md` populados em
`universes/REGISTRY.yaml` como entradas com status `planned` (open-source)
ou `external` (comerciais com lore aberta)

## So That

- Visitante abre o catálogo e vê **escala da promessa** — não é uma demo
  de 6 mini-games, é a fundação de um ecossistema
- Cada sistema vira candidato a contribuição: "quero portar Tagmar? Aqui
  está o placeholder, o card já existe, faltam: SRD em markdown +
  universe-tagmar WASM crate"
- Filtros dinâmicos (YG-70) ficam imediatamente úteis — `?origin=brazilian`
  retorna 40+ entradas, `?genre=horror` retorna BREU/Oblívio/Ordem
  Paranormal, etc

## Context

### Fonte: docs/RPGs Brasileiros.md

Documento já existente com ~40 sistemas mapeados, agrupados por tema/origem.
Cada sistema tem: nome, descrição curta, criador (quando conhecido),
publicação (independente ou editora).

### Classificação por status

| Critério | Status no REGISTRY |
|---|---|
| Open source declarado (Tagmar) | `planned` (potencial port para WASM universe) |
| Indie publicado livremente (download grátis) | `planned` |
| Comercial mas com SRD/lore aberto | `external` (link para site oficial) |
| Comercial proprietário (Tormenta, Ordem Paranormal) | `external` (link, sem port) |

### Estrutura por entrada

```yaml
- slug: tagmar
  status: planned
  type: rpg
  genre: [fantasy, medieval]
  origin: brazilian
  license: open-source
  title: "Tagmar 3"
  creators: ["Comunidade Tagmar"]
  year: 1991
  description: "O primeiro RPG nacional, criado em 1991. Continente dividido em três áreas: Região dos Reinos, Terras Selvagens e O Império. Desenvolvido como software livre desde a concepção."
  external_url: https://tagmar.com.br
  target_release: v1.5.0   # quando planejamos portar para WASM
  port_difficulty: medium  # easy | medium | hard
```

### Decisões a tomar (não bloqueiam esta task — descobrir conforme)

- Logos/cover art: licença? — placeholder genérico por gênero por enquanto
- "port_difficulty" é meu chute — confirmar com mantenedores quando
  iniciar conversa

## Acceptance

- `universes/REGISTRY.yaml` contém ao menos 30 entradas planned + 3-5
  external derivadas de `docs/RPGs Brasileiros.md`.
- `GET /api/v1/universos?origin=brazilian` retorna 35+ entradas.
- `GET /api/v1/universos?origin=brazilian&status=planned` retorna 30+.
- Frontend `/catalog` com filtro origin=brazilian renderiza grid com
  todos os 35+ cards.
- Cada entrada tem: slug, title, description (PT-BR), origin: brazilian,
  status (planned|external), license, target_release ou external_url.
- `docs/architecture/catalog.md` (do YG-70) ganha seção "RPGs brasileiros
  no catálogo" listando os critérios usados para classificação.
- Issue/discussion template em `.github/ISSUE_TEMPLATE/portar-rpg.md`
  (novo): "Quero portar <slug>" com checklist (contato com criador,
  licença confirmada, SRD em markdown, universe-<slug> crate, testes).

## Blast radius

Baixo — só dados (YAML) + um issue template. Sem código novo de runtime
além do que YG-70 já entrega.

## Out of scope

- Imagens reais de cada RPG (placeholders genéricos por gênero)
- Tradução EN das descriptions (i18n é v1.3.0)
- Implementação real de qualquer um dos RPGs portados (cada port = task
  separada YG-? quando priorizar)
