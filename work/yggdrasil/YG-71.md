## As

A maintainer querendo ver "o que mudou no universo X nas últimas N versões"
sem ter que extrair o crate para repo separado

## I Need

Tooling que gera/atualiza `universes/universe-X/CHANGELOG.md` automaticamente
a partir de um **filtro de git path** sobre o monorepo — equivalente
funcional a um submodule, mas sem o peso operacional de submodules de verdade

## So That

- Cada universo tem um histórico próprio rastreável (`git log`,
  `jj log <path>`, `gh blame`) sem migrar para repo separado
- O changelog do core fica focado em mudanças de plataforma
- Quando/se um universo for extraído para repo próprio (v2.x), o histórico
  filtrado vira a base do repo novo via `git filter-repo`

## Context

### Princípio: git pathspec é o submodule funcional

Para qualquer universo `universe-X`:

```bash
# Histórico desse universo só:
git log --follow --oneline -- universes/universe-X/

# jj equivalente (jujutsu):
jj log -p universes/universe-X/

# Diff entre duas versões:
git diff universe-X-v0.1.0..universe-X-v0.2.0 -- universes/universe-X/
```

Sem submodule. Sem `.gitmodules`. Sem submódulo. Cada universo é uma
**view filtrada** do mesmo repo.

### Tooling — `scripts/universe-changelog.sh`

```bash
$ bash scripts/universe-changelog.sh shandara
==> Generating universes/universe-shandara/CHANGELOG.md from git history
    Range: universe-shandara-v0.1.0..HEAD (3 commits)
    ✅ Updated universes/universe-shandara/CHANGELOG.md
```

Comportamento:

1. Lê a versão atual de `universes/universe-X/Cargo.toml`
2. Lê a tag mais recente do universo: `git tag --list 'universe-X-v*' | sort -V | tail -1`
3. Faz `git log <last-tag>..HEAD --pretty='%s%n%b%n---' -- universes/universe-X/`
4. Filtra para commits Conventional com escopo do universo: `feat(X):`,
   `fix(X):`, `feat(YG-N, X):` etc, OU qualquer commit que tocou o path
5. Reescreve a seção `[Unreleased]` do CHANGELOG.md do universo, agrupando
   por tipo (Added/Changed/Fixed)
6. Se passar `--bump <major|minor|patch>`, congela `[Unreleased]` como
   `[X.Y.Z] — <hoje>` e bumpa `Cargo.toml`

Convenções aceitas (em ordem de preferência):
- `feat(universe-shandara): ...` — escopo explícito por crate
- `feat(shandara): ...` — escopo curto (slug do universo)
- `feat(YG-N, shandara): ...` — combinação com task
- Qualquer commit que tocou `universes/universe-X/` — fallback

### Por que isso é jj-compatible

Jujutsu tem nativamente `jj log <path>` e mantém história por arquivo. O
script só usa `git log -- <path>` (ou pode optar por `jj log -p` se `jj`
estiver instalado, via flag `--use-jj`). Nenhuma operação destrutiva,
nenhuma reescrita de história — pure read-only sobre o repo.

### Por que não submódulos

| Problema do submodule | Solução pathspec |
|---|---|
| `.gitmodules` separado, fácil de esquecer atualizar | Nenhum arquivo extra |
| Clone shallow não pega submodules | Tudo é um repo só |
| Bisect cruza fronteira → confuso | Bisect funciona normal |
| PR que toca core + universo vira 2 PRs em 2 repos | Continua 1 PR |
| Operadores precisam aprender `git submodule update --init` | Não precisam aprender nada |

Vantagem do submodule real: independent visibility/permissions/CI por
universo. Quando isso virar requisito (v2.x), `git filter-repo` extrai
cada universo para um repo próprio preservando 100% da história filtrada.

### Hook opcional

Adicionar como `lefthook` step (se o usuário tem lefthook configurado):
```yaml
pre-commit:
  commands:
    universe-changelog:
      glob: "universes/universe-*/**/*"
      run: bash scripts/universe-changelog.sh --all --check
```

`--check` modo: falha se algum CHANGELOG está desatualizado em relação aos
commits no path. Não auto-edita no pre-commit (decisão de manter human in
the loop).

## Acceptance

- `scripts/universe-changelog.sh <slug>` existe, executável, gera/atualiza
  `universes/universe-<slug>/CHANGELOG.md` corretamente.
- `scripts/universe-changelog.sh --all` faz para todos os universos
  (lê lista de `universes/REGISTRY.yaml` filtrando `status: embedded` +
  `versions_tracked: true`).
- `scripts/universe-changelog.sh <slug> --bump patch|minor|major` congela
  `[Unreleased]` e bumpa Cargo.toml; valida que o bump é maior que a versão
  atual.
- `scripts/universe-changelog.sh --check` retorna exit 1 se algum universe
  changelog está atrás dos commits que tocaram seu path.
- `docs/UNIVERSE-VERSIONING.md` (do YG-67) documenta o script.
- Teste smoke: rodar para `universe-snake` em repo limpo gera saída válida
  (pode estar vazia se nenhum commit Conventional tocou o path).
- Sem dependência de jj, mas se `jj` estiver no PATH, log de boas práticas
  no header do CHANGELOG ("regenerated via git pathspec; jj-compatible").

## Out of scope

- Extração efetiva de universo para repo próprio (v2.x — usar
  `git filter-repo` quando vier).
- Geração automática de release notes em GitHub Releases (YG futuro).
- Versionamento semântico automático (lê labels do commit pra decidir o
  bump) — fica para uma v2 do script.

## Blast radius

Mínimo — só adiciona um script shell. Não toca código de produção, não
muda formato de commit (só padroniza o que já existe). Reversível
deletando o script.
