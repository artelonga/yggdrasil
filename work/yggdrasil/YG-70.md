## As

A visitor browsing the platform

## I Need

Um **catálogo de universos** que mostra muito além dos universos embedados —
inclui também universos planejados (placeholders) e externos (link out),
com filtros dinâmicos por tipo, gênero, origem, licença, status

## So That

A plataforma se posiciona como um *catálogo* de universos abertos (PT-BR
first, foco em RPG brasileiro), não apenas um lobby de mini-games. Visitantes
veem o tamanho da promessa, contribuidores veem onde podem ajudar, parceiros
veem o caminho de integração

## Context

### Mudança de framing

Hoje: "Yggdrasil é um lobby com 6 jogos."
Depois: "Yggdrasil é um catálogo de universos abertos — 6 já jogáveis aqui,
~50 mapeados como planejados ou externos, mais entrando."

### API — merge dinâmico

`GET /api/v1/universos` passa a retornar:

```json
{
  "universos": [
    { "slug": "snake", "status": "embedded", "version": "1.0.0",
      "type": "arcade", "playable": true, "title": "Snake", ... },
    { "slug": "tagmar", "status": "planned", "playable": false,
      "type": "rpg", "origin": "brazilian", "target_release": "v1.5.0", ... },
    { "slug": "ordem-paranormal", "status": "external", "playable": false,
      "external_url": "https://...", ... }
  ],
  "total": 53,
  "by_status": { "embedded": 7, "planned": 32, "external": 14 }
}
```

Filtros query string:
- `?status=embedded|planned|external|all` (default: all)
- `?type=rpg|arcade|puzzle|...`
- `?origin=brazilian|international|original`
- `?genre=fantasy,horror` (multi)
- `?license=open-source|commercial|all`
- `?search=tag` (substring match em title + description)

### UI

Página `/catalog` ou substitui o lobby atual:
- Grid de cards (status badge: 🟢 jogável / 🟡 planejado / 🔗 externo)
- Sidebar com filtros (checkbox por gênero, dropdown por origem, etc)
- Card embedado → "Jogar" → entra na universo via API existente
- Card planejado → "Em breve — contribuir" → link para issue/repo
- Card externo → "Saiba mais" → external_url em nova aba

## Acceptance

- `universes/REGISTRY.yaml` criado e populado com ao menos:
  - 7 embedados (6 atuais + shandara após YG-69)
  - 3-5 planejados de exemplo (incluindo tagmar, kilombo)
  - 2-3 externos de exemplo
- `yggdrasil-web/src/catalog.rs` (novo) lê REGISTRY.yaml em compile-time via
  `include_str!` + parse com `serde_yaml`.
- `GET /api/v1/universos` retorna o merge (embedded via WASM manifest +
  todas as entradas do REGISTRY) com os filtros listados acima funcionando.
- Backwards-compat: cliente que não passa filtros recebe o mesmo formato
  atual mais os novos campos (`status`, `playable`, etc são adicionados;
  campos antigos preservados).
- Frontend `yggdrasil-web/static/catalog.html` + `catalog.js`:
  - Renderiza cards com badge de status
  - Filtros funcionam client-side (re-query API com query strings)
  - Acessível por teclado, alto contraste
- Teste: 3 query strings diferentes retornam contagens corretas; placeholder
  cards têm `playable: false` no JSON.
- `docs/architecture/catalog.md` (novo) documenta o schema de REGISTRY.yaml.
- OpenAPI atualizado para refletir os novos campos.
