GIVEN signal bus + persistência prontos (YG-33) e auth Rust emite
JWTs (YG-11), mas Godot e Rust ainda vivem em mundos separados,
WHEN configuro `WebSocketMultiplayerPeer` no Godot server validando
JWTs com o mesmo `YGGDRASIL_JWT_SECRET` que o gateway Rust,
THEN dois browsers logados via `/login` (Rust) conseguem entrar no
mesmo `Lobby.tscn` e se ver — primeiro multiplayer real do POC.

## Arquitetura

```
Browser → /login (Rust :3030) → JWT em localStorage
       ↓
Browser → /games/lobby-godot (HTML estático servido pela Rust)
       ↓ carrega index.html do export Godot
Browser → WebSocket ws://host:3031/?token=<JWT>
       ↓
Godot headless server (:3031)
       ↓ verifica JWT com HS256 + YGGDRASIL_JWT_SECRET
       ↓ accept peer, spawna Player.tscn instance
```

Fly routes `/godot/ws` upgrades para `:3031` (mesma máquina, dois
processos no container OU dois containers).

## Critérios de aceitação

### Godot side

- [ ] `scripts/server_main.gd` — entrypoint para `--headless`:
  - [ ] `var peer = WebSocketMultiplayerPeer.new(); peer.create_server(3031)`.
  - [ ] `multiplayer.peer_connected.connect(_on_peer_connected)`.
  - [ ] `_on_peer_connected(id)` — valida JWT via packet inicial, kicka se inválido.
- [ ] `scripts/lib/jwt.gd` — implementa HS256 validation (Godot 4 tem
      `Crypto` class). Lê `YGGDRASIL_JWT_SECRET` de env var.
- [ ] `scripts/client_main.gd`:
  - [ ] Lê token de `JavaScriptBridge.eval("localStorage.getItem('yggdrasil-jwt')")` em web export.
  - [ ] Conecta com `?token=<jwt>` query.
- [ ] Lobby.tscn ganha:
  - [ ] `MultiplayerSpawner` para spawnar `Player.tscn` por peer.
  - [ ] `MultiplayerSynchronizer` em cada Player.tscn (sincroniza posição).

### Rust side (mínimo)

- [ ] `GET /games/lobby-godot` → serve `yggdrasil-godot/out/web/index.html`.
- [ ] `nest_service("/godot", ServeDir::new("yggdrasil-godot/out/web"))` para servir .wasm/.pck.
- [ ] Sem proxy WS no MVP — Fly expõe :3031 direto via `[[services]]` adicional em fly.toml.

### Deploy

- [ ] `fly.toml` ganha segundo service em `:3031` (TCP, ws, sem TLS terminate ou com proxy_protocol).
- [ ] `Dockerfile` (yggdrasil-web/Dockerfile já existe) refeito como multi-stage que produz **dois** binários:
  - [ ] `/usr/local/bin/yggdrasil-web` (Rust, :3030).
  - [ ] `/usr/local/bin/yggdrasil-godot` (Godot headless, :3031).
  - [ ] Process manager (supervisord ou s6-overlay) inicia ambos.

### Validação

- [ ] Dois browsers (perfis distintos) logam → entram `/games/lobby-godot` → cada um vê seu Player + o do outro.
- [ ] Movimento de A é visto por B em <200ms (gru → cliente residencial Brasil).
- [ ] Kill -9 do server: clientes desconectam graciosamente, reconectam após restart.
- [ ] JWT inválido: peer recusado com erro PT-BR logado no server.

## Não-objetivos

- Reconnect automático com backoff (defer).
- TLS no socket WS (Fly handles HTTPS upstream).
- Compartilhar sementes/wallet entre Godot e Rust (YG-35 trata).
