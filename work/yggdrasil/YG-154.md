GIVEN o YG-148 (mergeado) pôs a **engine real no instance view** (`MundoView`,
`mundo/loader.js` lê `InstanceStore`/`NoteStore`), MAS o YG-149 (PR #81) construiu o
**drag-drop+persist no surface ERRADO** — a página standalone `/mundo` (proto,
`window.__mundo`, `proto.js`) — porque forkou do main mock, ANTES do 148. Os dois
surfaces divergem: a engine real vive no `MundoView`, o drag-drop vive na página proto,

WHEN **salvarmos o BACKEND do YG-149** (que é surface-agnóstico e bom:
`instance/note.rs` persist de `pos{room,x,y}`/`parent` no frontmatter `.md`,
`api/instances.rs` PATCH layout, `co_bridge_producer.rs` write-back ao CO) e
**reimplementarmos só o FRONT** de drag-drop/reparent **sobre o `MundoView`** (a
engine real do 148, `mundo/loader.js`/`engine.js` no instance view) — não na página
proto standalone,

THEN o Mundo real (instance view) ganha **drag-drop que persiste no `.md`** e
**sincroniza com o CO**, num único surface coeso (sem Frankenstein proto-page + view).

## Referência
- PR **#81** (YG-149) tem o backend a salvar quase intacto — reusar `note.rs`,
  `api/instances.rs` (PATCH layout/place_block), `co_bridge_producer.rs`.
- O front do #81 (`static/universos/mundo/proto.js`, `window.__mundo`) é o que **NÃO**
  se reusa direto — a lógica (coordMap em memória → commit em lote → PATCH → write-back)
  migra pro `MundoView`/`loader.js` do 148.
- Fechar/superseder o #81 depois que este entrar (anotar no PR).

## Acceptance
- [ ] Backend do YG-149 presente: persist `pos{room,x,y}`/`parent` no `.md` (`note.rs`), PATCH layout (`api/instances.rs`), write-back CO (`co_bridge_producer`).
- [ ] Drag-drop/reparent **no `MundoView`** (instance view, engine real do 148) — NÃO na página proto standalone.
