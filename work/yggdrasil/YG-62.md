## As

A yggdrasil platform operator

## I Need

Tabelas `funnel_events` e `session_records` no SQLite existente, instrumentadas nos
endpoints de sessão unificados (YG-60), e um endpoint `/api/v1/admin/analytics` com
métricas básicas de funil e engajamento por universo

## So That

Após o release v1.0 tenho visibilidade sobre quais universos têm mais sessões,
taxa de conclusão, duração mediana — dados necessários para priorizar o roadmap
pós-release e para a campanha de financiamento

## Context

- **Princípios:** §8 (telemetria persistente, não apenas logs)
- **Depende de:** YG-60 (rotas unificadas — pontos de instrumentação)
- **Independente de:** YG-55/56/57/58 — pode ser desenvolvida em paralelo,
  mas só integrada após YG-60 existir
- **Schema** (migration idempotente no boot via `init_telemetry_db(conn)`):
  ```sql
  CREATE TABLE IF NOT EXISTS funnel_events (
      event_id   TEXT    PRIMARY KEY,
      user_id    TEXT,
      session_id TEXT,
      universe_id TEXT,
      event_type TEXT    NOT NULL,
      properties TEXT,                -- JSON livre
      created_at INTEGER NOT NULL     -- Unix ms
  );
  CREATE INDEX IF NOT EXISTS idx_funnel_universe
      ON funnel_events(universe_id, created_at);
  CREATE INDEX IF NOT EXISTS idx_funnel_user
      ON funnel_events(user_id, created_at);

  CREATE TABLE IF NOT EXISTS session_records (
      session_id  TEXT    PRIMARY KEY,
      user_id     TEXT,
      universe_id TEXT    NOT NULL,
      started_at  INTEGER NOT NULL,
      ended_at    INTEGER,
      duration_ms INTEGER,
      final_score INTEGER,
      abandoned   INTEGER NOT NULL DEFAULT 0
  );
  ```
- **Event types instrumentados (v1.0):**
  - `SESSION_CREATE` — em `POST /api/v1/universos/{id}/sessoes`
  - `SESSION_COMPLETE` — em `DELETE /sessoes/{sid}` com score final
  - `SESSION_ABANDON` — cleanup job detecta sessões sem activity > 30min
  - `UNIVERSE_VIEW` — em `GET /api/v1/universos/{id}`
- **Cleanup job:** `tokio::spawn` com `interval(Duration::from_secs(300))` que
  marca sessões inativas como `abandoned = 1` e emite `SESSION_ABANDON`.
- **`GET /api/v1/admin/analytics`** (protegido por `YGGDRASIL_ADMIN_TOKEN`):
  ```json
  {
    "generated_at": "2026-05-20T12:00:00Z",
    "period": "24h",
    "universos": [
      {
        "id": "snake",
        "sessions_today": 42,
        "completions_today": 18,
        "completion_rate_pct": 43,
        "median_duration_ms": 95000,
        "active_now": 3
      }
    ],
    "funnel_24h": {
      "universe_views": 120,
      "session_creates": 48,
      "session_completions": 31,
      "conversion_view_to_create_pct": 40,
      "conversion_create_to_complete_pct": 65
    }
  }
  ```
- **Não usar ORM** — queries SQL diretas via `rusqlite` (mesmo padrão de `poker_persistence.rs`).
- Referência: `docs/PLATAFORMA-UNIVERSOS.md §6` e `docs/RELEASE-V1.md §Epic 7`.

## Acceptance

- Migration `init_telemetry_db()` é idempotente — rodar duas vezes não cria tabelas duplicadas.
- `SESSION_CREATE` registrado em `funnel_events` e `session_records` para cada chamada
  a `POST /api/v1/universos/{id}/sessoes`.
- `SESSION_COMPLETE` registrado com `final_score` e `duration_ms` corretos.
- Cleanup job marca sessões sem tick há > 30min como `abandoned = 1` (testável com
  `tokio::time::pause()` + `advance()`).
- `GET /api/v1/admin/analytics` retorna JSON com campos `universos` e `funnel_24h`.
- `GET /api/v1/admin/analytics` sem token retorna 401.
- Queries SQL terminam em < 50ms com 10.000 registros em `funnel_events`
  (testar com dataset gerado).
- `cargo test` passa; telemetria testada com `tempfile::tempdir()` para o SQLite.
