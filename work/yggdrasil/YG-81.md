## As

Um usuário que quer **construir/editar** o próprio universo (estilo Sims/Paralives)

## I Need

Um **modo de edição** no player: sidebar de paleta, colocar/mover/apagar blocos na
grade, slider de opacity por layer, criar conexões, e fazer upload de anexos —
tudo persistido via os endpoints REST

## So That

O loop completo de autoria fecha: a partir de um template, o usuário monta o
universo dele direto no navegador, sem escrever código

## Context

Ler `docs/architecture/editor.md` (§ "Runtime/serving" — "O editor é o mesmo player
+ paleta + affordances"). Estende o player read-only de YG-78; mesma página/JS, com
um toggle "modo edição" (visível só para o owner).

### Interações → endpoints (todos já existentes em YG-76/YG-77)

- **Colocar bloco:** selecionar `block_type` na paleta, clicar célula →
  PATCH `PlaceBlock`.
- **Mover bloco:** arrastar → PATCH `MoveBlock`.
- **Apagar bloco:** selecionar + delete → PATCH `DeleteBlock`.
- **Opacity de layer:** slider por layer → PATCH `EditLayer{opacity}` (debounced).
- **Conexão:** modo "conectar", clicar bloco A depois bloco B → PATCH
  `AddConnection`; apagar → `DeleteConnection`.
- **Anexar:** botão upload no inspector do bloco → POST `/attachments` →
  PATCH `AttachContent` com o `ContentRef` retornado.
- **Paleta:** carregada de `GET /api/v1/templates/{slug}` (block_types + props
  default + ícones).

UI consistente com o front-end existente (canvas + vanilla JS, PT-BR, acessível).
Feedback otimista com reconciliação no retorno do PATCH; em erro de validação
(422/409), reverter e mostrar mensagem.

## Acceptance

- `instance.js`/`instance.html` ganham modo edição (gate por ownership) com:
  sidebar de paleta, place/move/delete de bloco, slider de opacity por layer,
  criar/apagar conexão, e upload+attach.
- Cada ação dispara o PATCH/POST correto e persiste; recarregar a página reflete o
  estado salvo.
- Slider de opacity persiste via `EditLayer` (debounced) — recarregar mantém o
  valor; o toggle de transparência do SNC (template neuroanatomia) funciona como
  edição persistida, não só view.
- Erros de validação do servidor (422/409/403) revertem o estado otimista e exibem
  mensagem PT-BR.
- Não-owner vê o player em modo read-only (sem affordances de edição).
- Smoke E2E manual (documentado no CHANGELOG/PR): template neuroanatomia → mover um
  landmark → adicionar conexão → upload de um PDF num landmark → reload confirma
  tudo persistido.
- Acessível por teclado, alto contraste. `clippy -D warnings`/`fmt` limpos (lado
  Rust, se houver); sem framework JS pesado.
- CHANGELOG `[Unreleased]`; bump minor.
