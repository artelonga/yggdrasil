## As

A platform que quer que usuários **criem e editem universos**, não apenas joguem
os arcade embedados

## I Need

Um **editor estilo The Sims / Paralives**: colocar blocos numa grade 2D
(isométrica depois) para gerar novos universos e editar os próprios, anexando
conteúdo multiformato (arquivos, metadata, analytics, PDF/imagem/som — reusando
a compatibilidade de arquivos do `co`) a cada bloco. Primeiro caso concreto:
**neuroanatomia** (silhueta do corpo + overlay do SNC com toggle de transparência,
landmarks anatômicos e conexões entre eles)

## So That

- A plataforma deixa de ser só um lobby de arcade WASM e passa a ser uma
  ferramenta de **autoria** de universos — o pilar que sustenta a tese de
  "universos são ecossistemas expansíveis".
- Universos autorados são **dados carregados em runtime**, não crates compilados
  — qualquer usuário cria sem escrever Rust.
- Neuroanatomia valida o formato genérico num domínio real (educacional,
  open-source) e vira o primeiro de muitos templates.

## Context

**Lacuna central:** hoje todo universo é código (crate Rust → WASM embutido via
`include_bytes!` em `yggdrasil-web/src/wasm_runtime.rs`). Os front-ends (Godot 4.5
e web canvas) são players finos. Universos autorados precisam de um conceito novo
e **paralelo** ao runtime WASM: `UniverseInstance` — dado puro renderizado por um
player genérico client-side.

A arquitetura completa (formato serde, contrato REST, persistência, template,
fontes open-source de anatomia) está em **`docs/architecture/editor.md`** — ler
antes de qualquer story. Decisões-chave:

1. **Formato host-neutral + REST API primeiro.** A fronteira estável é o JSON +
   endpoints; escolher Godot vs web como host do editor é fase posterior.
2. **Editor genérico primeiro.** Neuroanatomia é o primeiro template.
3. **Aditivo.** Zero mudança no runtime WASM, no `universe-sdk`, nos routers de
   arcade ou no `default_registry()` hardcoded.

## Acceptance

- `docs/architecture/editor.md` existe e documenta formato + contrato REST +
  persistência + template + fontes open-source (esta story entrega o doc).
- As 8 stories filhas (YG-74…YG-81) estão criadas em `work/yggdrasil/` com
  frontmatter consistente (`module: editor`, `parent: 73`, `blocked_by` conforme
  o grafo).
- Ao fim do epic: um usuário autenticado cria uma instância a partir do template
  `neuroanatomia`, faz upload de SVGs (silhueta + SNC), posiciona landmarks,
  conecta-os, e abre `/universos/instance/{id}` — renderiza com slider de
  transparência funcionando, anexos abríveis ao clicar landmarks.
- Os universos arcade existentes continuam intactos (smoke test de
  `/universos/snake`) — nada no runtime WASM/SDK/registry foi tocado.

## Blast radius

Grande no agregado, mas cada story é aditiva e isolada. Novo módulo
`yggdrasil-core/src/instance/`, novo router `yggdrasil-web/src/api/instances.rs`,
nova tabela SQLite `instances`, nova página estática. Nenhum arquivo de arcade,
do `universe-sdk` ou do registry hardcoded é modificado. Nova dependência por path
em `co/core` (decisão em aberto #1 do doc de arquitetura).
