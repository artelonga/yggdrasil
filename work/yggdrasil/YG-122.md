## As
A federação ao vivo — bloqueada: o handshake do producer é **recusado pelo CO-384** (HTTP 400).

## I Need
Que o request de upgrade do dial (`ws_request`/`connect_and_stream`, YG-119/120) seja **aceito
pelo `axum::extract::ws::WebSocketUpgrade`** do CO-384 — hoje ele responde
`400 "Connection header did not include 'upgrade'"`.

## So That
A conexão completa (`bridge.connected{source=yggdrasil...}` no CO), e os termos/notas federam.
Sem isso o producer fica em loop de reconnect 2s — "federação ligada, zero tráfego".

## Context — PEGO NO PRÉ-FLIGHT (2026-06-09)
E2E local (co-web debug + yggdrasil-web debug, bridge `ws://127.0.0.1:8742`):
- producer ativa, semeia 116 termos, dia o hub. ✅
- CO-384 route é real (400 WS-upgrade, não SPA). ✅
- **handshake → `HTTP error: 400 Bad Request`** do `WebSocketUpgrade` do axum; CO loga
  "Connection header did not include 'upgrade'". ❌ Sem `bridge.connected`.

**Falso-positivo do teste:** o `integracao_ws_mock_handshake_drain_e_ack` (YG-119) usa um
servidor `tokio-tungstenite` `accept_hdr_async` (lenient) que aceita o handshake; o
`WebSocketUpgrade` do axum (estrito) recusa. O mock deu confiança falsa.

**Hipótese:** `ws_request` monta o request via `into_client_request()` + `headers_mut().insert(...)`
e passa o `Request<()>` pré-construído a `connect_async`. O request que chega ao axum não tem o
`Connection: upgrade`/`Upgrade: websocket`/`Sec-WebSocket-Key/Version` válidos como o axum exige
(provável interação do request pré-construído + headers manuais + query `?source=&token=`).

## Acceptance
- **GIVEN** um servidor **axum** com `WebSocketUpgrade` (igual ao CO-384) num porto efêmero
  **WHEN** o producer disca  **THEN** o handshake é **aceito** (101 Switching Protocols), o
  subprotocol `co.eda.bridge.v1` negocia, e o socket abre.
- **GIVEN** o E2E local (co-web + yggdrasil-web)  **WHEN** ligados  **THEN** CO loga
  `bridge.connected{source=yggdrasil.artelonga.com.br}` e um termo publicado chega ao CO.
- **ENDURECER:** trocar o mock `tokio-tungstenite` por um **servidor axum real** no teste de
  integração (ou adicionar um), p/ pegar essa classe de bug. (O mock lenient mascarou.)

## Notas de implementação
- Diagnosticar capturando os headers que o `connect_async` de fato envia (vs o que o
  `WebSocketUpgrade` exige). Possível fix: deixar o tungstenite gerar o handshake nativamente
  (sem pré-construir/inserir manualmente os headers de upgrade), anexando só auth/subprotocol da
  forma suportada; ou usar `connect_async_with_config`.
- Re-validar contra o **co-web local** (harness do pré-flight, comprovado) antes de prod.

## Dependencies
- YG-119/120 (o dial). **Bloqueia YG-121 (go-live)** — não cutar v3.0 até o handshake local passar.
