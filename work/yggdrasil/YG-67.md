## As

Anyone shipping a universe change

## I Need

Uma convenção documentada para taggear releases de universo no monorepo, e
regras claras de quando bumpar major/minor/patch de um universo vs. do core

## So That

Releases ficam rastreáveis (`git log --tags`) e o co-auto sabe quais commits
exigem bump de versão e em qual escopo (universe-X vs. yggdrasil core)

## Context

- Tag format proposto:
  - Core: `v<X.Y.Z>` (mantém o existente — `v1.0.0`)
  - Universe: `universe-<nome>-v<X.Y.Z>` (ex.: `universe-poker-v0.9.0`)
- Regras de bump por universo (Keep a Changelog + SemVer):
  - **major** — quebra de input/output JSON do tick, mudança de manifest
    incompatível, remoção de funcionalidade que clientes consumiam
  - **minor** — novo nível/conteúdo, nova capability adicionada ao manifest,
    novo evento emitido via `emit_event` (consumível mas opcional)
  - **patch** — bug fix, ajuste de balanceamento, melhoria visual sem mudança
    de protocolo
- Regras de bump no core quando um universe muda:
  - Bump de patch/minor de universe → **patch** do core (rebuild WASM, novo
    binário; sem mudança de API)
  - Bump de major de universe → **minor** do core (mudança comportamental
    visível para clientes)
  - Mudança no `universe-sdk` ABI → **major** do core (todas as universes
    precisam recompilar)
- Workflow proposto:
  1. Mudar código em `universes/universe-X/`
  2. Bump em `universes/universe-X/Cargo.toml`
  3. Atualizar `universes/universe-X/CHANGELOG.md`
  4. Bump do core (patch) em `Cargo.toml` + `CHANGELOG.md` raiz
  5. Commit: `feat(universe-X): descrição`
  6. Tag dupla: `universe-X-v<new>` E `v<core_new>` (ou só uma se for o
     primeiro bump pendente do core)

## Acceptance

- `docs/UNIVERSE-VERSIONING.md` criado com:
  - Tabela de tipos de mudança → bump (universe vs core)
  - Convenção de tag format
  - Workflow passo-a-passo para shipar mudança em um universo
  - Exemplo end-to-end (commit + bump + tag + push)
- `CLAUDE.md` (root + `work/yggdrasil/CLAUDE.md`) referencia o documento.
- `universes/README.md` (do YG-65) linka para `docs/UNIVERSE-VERSIONING.md`.
