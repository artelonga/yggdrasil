GIVEN o scaffold do projeto Godot existe (YG-31),
WHEN crio o primeiro nível de composição — uma `Lobby.tscn` que
instancia 4 `GamePortal.tscn` (cada um com slug + tile alvo) e um
`Player.tscn` controlável,
THEN provo que cenas nestadas em Godot substituem o modelo
`yggdrasil-core::lobby` + canvas/JS sem regressão funcional para
single-player.

## Critérios de aceitação

- [ ] `scenes/Player.tscn` — CharacterBody2D com sprite simples,
      WASD/setas, sinal `signal entered_portal(slug: String)`.
- [ ] `scenes/GamePortal.tscn` — Area2D + Sprite2D + Label,
      `@export var slug: String`, `@export var titulo: String`,
      sinal `signal player_entered(slug, player_id)` emitido ao body_entered.
- [ ] `scenes/Lobby.tscn` — composição:
  - [ ] 4 instâncias de `GamePortal.tscn` (snake/tetris/invaders/poker).
  - [ ] 1 instância de `Player.tscn`.
  - [ ] Background tile-based simples (TileMap ou ColorRect).
  - [ ] Posições espelham `yggdrasil-core::lobby::pos` (10,8 / 30,8 / 10,12 / 30,12).
- [ ] Conexão de sinais:
  - [ ] `Lobby.gd` escuta `player_entered` de cada portal.
  - [ ] No callback: `print("entered portal: ", slug)` (próxima tarefa transforma em transição real).
- [ ] Acessibilidade básica:
  - [ ] Tab navega entre portais (mesmo sem mouse/teclado).
  - [ ] Texto dos labels usa fonte sistema, alto contraste.
- [ ] Funciona idêntico em browser (web export) e desktop (`godot scenes/Lobby.tscn`).
- [ ] Demonstra **nested scenes**: GamePortal.tscn não conhece Lobby.tscn; Lobby.tscn instancia múltiplas cópias.
- [ ] Documentar em `yggdrasil-godot/README.md` como adicionar um 5º portal sem tocar em Lobby.tscn (só editar o registry yaml — ver próxima tarefa).

## Não-objetivos

- Multiplayer (YG-34).
- Carregar a scene do universo destino ao entrar no portal (YG-33 trata transição via signal).
- Pathfinding tipo BFS (Godot tem navigation server; deixar para fase de polimento).
