GIVEN o registro de universos existe (YG-36) com variantes carregando
`parameters: BTreeMap<String, Value>`, mas as rotas
`/api/v1/games/{slug}/start` ainda ignoram `?variant=<slug>`,
WHEN cada rota de jogo lê o query param `variant`, consulta o
`UniverseRegistry`, e aplica `parameters` na inicialização do engine,
THEN escolher `snake/walls` no lobby de fato gera um mapa com paredes,
`tetris/sprint-40` termina em 40 linhas, `invaders/swarm` começa com
1 vida, e `poker/heads-up` provisiona uma mesa de 2 assentos.

## Mudança comum

Em cada `*_routes.rs`:

1. Adicionar `Query(params)` extractor com `variant: Option<String>`.
2. Resolver no registro: `registry.get(&variant).and_then(|n| n.parameters)`.
3. Se a variante não existir, comportar como root (default) — não 404.
4. Passar os `parameters` para o construtor da sessão de jogo.

A registry passa a ser injetada como `Arc<UniverseRegistry>` em todos
os States de jogo. Para evitar acoplamento circular, cada rota tem sua
própria função `apply_parameters(state, params)` em `<game>.rs` do core.

## Critérios de aceitação

### Snake (`yggdrasil-core::games::snake::YggSnake`)

- [ ] Aceita `map: &str` — `"empty"` (default) ou `"walls"`.
- [ ] `"walls"` adiciona ≥ 3 obstáculos `Tile::Wall` em posições
      determinísticas (seed = id da sessão).
- [ ] Aceita `difficulty: &str` — `"easy"|"medium"|"hard"`. Afeta a
      velocidade inicial (tick interval). Default: `"medium"`.
- [ ] `snake_routes::start_game` lê `?variant=snake/walls` e aplica.
- [ ] Teste: `snake/walls` produz pelo menos 1 wall tile no mapa
      retornado em `state`.

### Tetris (`yggdrasil-core::games::tetris::YggTetris`)

- [ ] Aceita `mode: &str` — `"marathon"` (default) ou `"sprint"`.
- [ ] Aceita `lines_to_clear: u32` — só relevante em `"sprint"`.
- [ ] Em sprint, ao limpar N linhas, sessão encerra com
      `game_over=true` + `winner_message = "Sprint completo: <N> linhas"`.
- [ ] `tetris_routes::start_game` lê variant e aplica.
- [ ] Teste: `tetris/sprint-40` termina mão após simular 40 line clears.

### Invaders (`yggdrasil-core::games::invaders::YggInvaders`)

- [ ] Aceita `lives: u32` — default 3.
- [ ] Aceita `difficulty: &str` — afeta velocidade horizontal dos aliens
      e frequência de tiros.
- [ ] `invaders_routes::start_game` lê variant.
- [ ] Teste: `invaders/swarm` começa com 1 vida no estado inicial.

### Poker (`yggdrasil-core::games::poker_game::PokerTable`)

- [ ] `PokerTable::new` aceita `max_seats: usize` (default
      `poker_lobby::SEATS_PER_LOBBY = 6`).
- [ ] `PokerTable::sit_with_sementes` aceita `buy_in: u64` (default
      `BUY_IN_SEMENTES = 1_000`).
- [ ] `PokerState::new` provisiona mesas usando variantes da registry:
  - [ ] `poker/cash-game` → "Mesa Carvalho" + "Mesa Olmo" (6 seats, 1000 buy-in)
  - [ ] `poker/heads-up` → "Heads-Up Carvalho" + "Heads-Up Olmo" (2 seats, 1000 buy-in)
- [ ] Teste: lobby de `poker/heads-up` rejeita o 3º humano com
      `LobbyError::InvalidSeat` adaptado.

### Frontend

- [ ] `lobby.js` portal navigation aceita variant: ao clicar num portal,
      lê `?variant=<slug>` se o tile tiver metadata de variante. Hoje
      navegação é `/universos/${slug}` — vira `/universos/${slug}?variant=${vslug}`.
- [ ] (Stretch) `/universos/{slug}` lê `?variant=` e exibe título +
      descrição da variante no header da página.

### Documentação

- [ ] `docs/ARQUITETURA-UNIVERSOS.md` ganha exemplo concreto de fluxo:
      "como adicionar uma variante" — passos do `UniverseNode::variant()`
      até o parâmetro chegando no engine.

## Não-objetivos

- **UI para escolher variante no lobby**: hoje variantes só são
  acessíveis via URL direta. Picker visual no lobby vem depois.
- **Variantes user-generated**: registry permanece estático.
- **Composições funcionais**: `tetris/duel` permanece como metadata —
  combinar dois engines é tarefa separada (estado compartilhado, UI
  split-screen, etc).

## Por que importa

Sem esta tarefa, o grafo de universos é apenas decoração. Com ela,
"cada variante é um universo de verdade" deixa de ser slogan e vira
contrato verificável: o cliente que abrir `/universos/snake?variant=snake/walls`
joga uma versão DIFERENTE de snake — mesmo engine, regras alteradas,
score table separada (eventualmente).
