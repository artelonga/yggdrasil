## As

A developer construindo o editor de universos

## I Need

O **formato data-driven** `UniverseInstance` como structs serde em
`yggdrasil-core/src/instance/schema.rs`, com round-trip serialização estável e
`schema_version = 1`

## So That

Existe uma fronteira de dados estável e versionada sobre a qual o store, a API e
o player são construídos — independente de qualquer front-end (Godot ou web)

## Context

Ler `docs/architecture/editor.md` (§ "Formato"). Conceito **paralelo** ao
`UniverseNode`/`UniverseKind` de `yggdrasil-core/src/universes.rs` — NÃO um novo
`UniverseKind`. Novo módulo `yggdrasil-core/src/instance/` (`mod.rs`, `schema.rs`;
`store.rs`/`template.rs` vêm em stories seguintes).

Structs a implementar (assinaturas completas no doc de arquitetura):

- `UniverseInstance { id, schema_version:u32, owner, title, description, template,
  grid:GridSpec, projection:Projection, layers:Vec<Layer>,
  connections:Vec<Connection>, meta:BTreeMap, created_at, updated_at }`
- `GridSpec { width, height, cell_size }`
- `Projection { TwoDGrid, Isometric }` — `#[serde(rename_all="snake_case")]`
- `Layer { id, name, kind:LayerKind, visible, opacity:f32, background:Option<ContentRef>, blocks:Vec<Block> }`
- `LayerKind { Background, Blocks, Annotation }`
- `Block { id, block_type:String, pos:Cell, label:Option<String>, attachments:Vec<ContentRef>, props:BTreeMap }`
- `Cell { x:u32, y:u32 }`
- `Connection { id, from, to, label:Option<String>, directed:bool, props:BTreeMap }`
- `ContentRef { kind:AttachmentKind, hash, filename, mime, size:u64 }`
- `AttachmentKind { Pdf, Image, Sound, Markdown, Metadata }`

Diferente de `UniverseNode`, `UniverseInstance` deriva **`Deserialize`** além de
`Serialize`. Campos opcionais com `#[serde(default)]` (label, attachments, props,
background, meta, directed). Datas via `chrono::DateTime<Utc>` (já em uso no repo,
ver `telemetria.rs`/`sementes.rs`).

Sparse de propósito: blocos por coordenada (`Vec<Block>` com `pos:Cell`), não
matriz densa `Vec<Vec<Tile>>` como `game-core::Map`. NÃO estender `Map`/`Tile`.

## Acceptance

- `yggdrasil-core/src/instance/schema.rs` define todas as structs/enums acima com
  `derive(Debug, Clone, Serialize, Deserialize)` (e `Copy/PartialEq/Eq` onde fizer
  sentido: `Cell`, `Projection`, `LayerKind`, `AttachmentKind`).
- `yggdrasil-core/src/instance/mod.rs` reexporta o schema; `lib.rs` declara
  `pub mod instance;`.
- `schema_version` é `u32` com constante `pub const SCHEMA_VERSION: u32 = 1;`.
- Teste de round-trip: construir uma `UniverseInstance` neuroanatomia de exemplo
  (2 layers Background com opacity diferentes + 1 layer Blocks com 2 landmarks +
  1 Connection), serializar para JSON, desserializar, `assert_eq!` idêntico.
- Teste de ambas projeções (`TwoDGrid` e `Isometric`) serializam para as strings
  snake_case esperadas (`"two_d_grid"`, `"isometric"`).
- `cargo test -p yggdrasil-core` passa; `cargo clippy --workspace -- -D warnings`
  limpo; `cargo fmt --all -- --check` limpo.
- CHANGELOG `[Unreleased]` atualizado; bump minor.

## Blast radius

Mínimo — só adiciona um módulo em `yggdrasil-core`, sem rotas nem persistência.
Nenhum código existente é modificado (espelha como `universes.rs` veio antes das
suas rotas).
