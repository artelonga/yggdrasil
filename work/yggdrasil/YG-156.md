## Decisão (ADR — documentada por ultrathink)
O `mundo/loader.js` divergiu em PRs paralelos: **154 (mergeado)** = loader **eager**
(`build()`→`byId` de TODAS as salas, depois `applyLayout` move/posiciona notas pelo
`.md`); **151 (PR #85)** = loader **lazy** (`ids` + `get(id)` constrói UMA sala sob
demanda — o vault inteiro sem estourar memória). **Decisão: a base é o loader LAZY
(151)** — memory-light é requisito do dono; o drag-drop durável do 154 **folda** nele.
Resolver por merge textual produz código que *compila mas quebra em runtime* (o
`findNote` do 154 varre um `byId` que o lazy não tem) → reimplementar limpo sobre o
base mergeado, como 149→154.

## O que construir (sobre o main atual, que já tem 154)
### `mundo/loader.js` — loader lazy COM layout persistido folado
- Manter `{ rootId, ids, get }` (151) + expor **`roomOf(slug)`**.
- **Pré-computar overrides** do `.md` (uma passada barata, sem layout):
  `layoutOverride[slug] = { room?, x?, y? }` de `n.parent || n.pos.room`, `n.pos.x/y`.
- **Membership efetiva** (reparent): `notesInRoom[room] = [meta]` onde
  `room = layoutOverride[slug].room || (parentOf[block] || ROOT_ID)`. Assim `get(id)`
  inclui notas reparenteadas PRA `id` e exclui as movidas pra FORA — sem construir
  outras salas.
- `get(id)`: `doorItems` = pastas-filhas estruturais; `noteItems` = `notesInRoom[id]`;
  **após `layoutRoom`**, sobrepor `x/y` de `layoutOverride` em cada objeto.
- `roomOf(slug)` = a sala efetiva da nota (lookup em notesInRoom/override) — pro
  `findNote`/`posOf` acharem a nota sem construir tudo.

### `mundo/instance-view.js` — API união
- Manter de **151**: `get rooms()` → `rooms.ids`, `get fullscreen()`, `toggleFullscreen`.
- Manter de **154**: `enter`, `posOf`, `drag`, `reparent`.
- **`findNote(slug)`** re-apontado: `const rid = loader.roomOf(slug); const r = loader.get(rid); …`
  (NÃO varrer `byId` — não existe no lazy). `room(id)` = `loader.get(id)`.
