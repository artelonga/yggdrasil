## As
Quem anota e age: ideias e pendências moram no mesmo universo.

## I Need
**Composição sobre herança**: `Note.status: Option<status>` no frontmatter
(`todo|doing|done`). Nota com status É tarefa; limpar o status devolve a nota.
Zero tipos novos, zero storage novo — o markdown canônico ganha um campo.

- Composer: `[] texto` cria tarefa (idioma checkbox markdown); `[x]`=feita,
  `[~]`=fazendo.
- Grade: rótulo com ☐/◐/☑; Árvore TUI: `[ ]`/`[~]`/`[x]` clicável (cicla).
- Inspetor da nota: chips nota · ☐ a fazer · ◐ fazendo · ☑ feita.
- API: `PUT notes/{slug}` aceita `status` opcional (ausente preserva; `""`
  limpa); resposta e federação (frontmatter do NoteWritten) carregam o status.

## Acceptance
- GIVEN `[] comprar tinta` no composer THEN nota criada com status=todo,
  ☐ na grade e `[ ]` na árvore.
- GIVEN clique no `[ ]` da árvore THEN cicla todo→doing→done→todo.
- GIVEN PUT sem campo status THEN o status existente é preservado (editar o
  corpo não destarefa); `status:""` limpa (vira nota).
- GIVEN round-trip do markdown THEN `status:` sobrevive parse/serialize.
- GIVEN nota federada THEN o NoteWritten leva o status no frontmatter.
