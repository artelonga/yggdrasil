## Feedback (usuário)
"Um universo criado por um usuário vira um universo novo em CO; o usuário pode
convidar quem quiser ou deixar público pra subscribe."

## Escopo
- Criar universo no yggdrasil (instância autorada, YG-126) → propaga ao CO como
  universo novo (parent_key = perfil/yuri-style), via bridge ou API do CO.
- Convites (lista de e-mails) e modo público-subscribable.
- Compor sobre o perfil universal (YG-137): "meus universos" = onde sou dono +
  onde tenho perfil.

## DESBLOQUEADO (2026-06-14) — a API do CO já existe
A investigação anterior ("não é user-facing") está **obsoleta**. O CO expõe, com
auth de usuário (`UserId`), tudo o que YG-138 precisa (`co/co-web/src/content/
universe/routes.rs`, CO-444):
- `POST /api/v1/universes` — cria universo (caller vira owner), aceita
  `parent_key` (validado) + `visibility` (private/public) + quota por tier.
- `GET /api/v1/me/universes` — buckets owned/subscribed/invited (= "meus universos").
- `GET/POST/DELETE /api/v1/universes/:key/members` — membros/convites.
- `GET /api/v1/universes/public` + `POST /api/v1/universes/:slug/subscribe`.

Resta só a **integração no lado yggdrasil** (chamar essas rotas como o usuário) +
uma decisão de auth/UX (redirect-to-CO vs server-to-server com token handover).
Pré-requisito: criar universo autorado no yggdrasil (YG-126).

## Acceptance (quando desbloqueado)
- GIVEN usuário cria universo no yggdrasil THEN aparece no CO como universo dele.
- GIVEN convite/público THEN terceiros acessam/subscribe conforme a visibilidade.
