## Visão
Caminhar pelo universo como num jogo 2D: **pasta = sala** (pisar na porta entra),
**nota = objeto** (pisar abre/edita), **arrastar** organiza e a **árvore** atualiza
em tempo real, **NPC** (LLM) ensina. Inspiração Tibia (salas/tiles) + Gather (zonas
de interação). Salas single-user agora; multiplayer depois (presença YG-145 já é o
substrato). Tema default + temas plugáveis (forma+arte, não só cor).

## Arquitetura do produto (consolidada)

### 1. Engine plugável + compatibilidade Godot
Componentes **engine-neutros por contrato** (não por linguagem):
- `Room` (dado): grade + entidades (`doors`/`notes`/`npcs`/`exit`/`spawn`) — JSON.
- `Theme` (dado/manifest): paleta + métricas + sprites (procedurais hoje; imagens
  depois — mesma interface).
- `Interactions`/`Editor`: eventos (`enter`, `open`, `drag-drop`, `reparent`).
Hoje cliente = **canvas** (leve, mobile, reusa lobby.js). **Godot vira um cliente
alternativo** consumindo o MESMO backend + Room JSON + Theme manifest, exportado
web e servido como `/anatomia` (Godot não está instalado nesta máquina → fase
própria com toolchain). "Garantir compat Godot" = manter esses contratos
desacoplados da engine. Diagonais/aceleração já provam que canvas dá conta do
movimento; Godot entra por animação/física/netcode ricos.

### 2. Conteúdo = `.md` + metadados, modelo de **grafo**
- **Canônico**: cada nó = arquivo `.md` com **YAML frontmatter**
  (`title, type, status, parent, links[], pos{room,x,y}`). Pasta = nó com filhos /
  índice. Fonte de verdade (alinhado a CO e ao markdown-canônico do projeto).
- **Estado/forma mora no frontmatter** (`pos`) — assim **layout replica como
  conteúdo** (round-trip pelo bridge de graça).
- **Em memória**: grafo (protobuf/struct) nós + arestas tipadas
  (`parent`/`ref`/`wikilink`/`sibling`) — o runtime que o Mundo lê/escreve.
  **Graph-DB-ready**: o mesmo modelo encaixa num graph DB depois sem mudar o `.md`.

### 3. API CRUD compatível com CO
Espelha o contrato de conteúdo do CO p/ replicar quando o usuário **confirma**:
- Reusa o que já existe: `…/instances/{id}/notes/{slug}` (GET/PUT/DELETE) +
  draft (YG-125). Notas já aterrissam no CO como entries (YG-97/121).
- **Novo**: `PATCH …/notes/{slug}/layout` (pos/state) e
  `POST …/instances/{id}/bundle` (commit atômico de N ações).
- Replicação CO: posição vai no frontmatter → vira conteúdo → bridge replica;
  edição volta via CO-413 (bidirecional).

### 4. Confirm-to-commit + state-map + bundle/backup
- O Mundo mantém **working copy em memória**: `coordMap` (estado/forma) + edições
  de conteúdo pendentes. Um único gesto muda **conteúdo OU estado**.
- **Confirma** = drag-release em tile diferente / salvar nota → enfileira ação.
- Ações são **agrupadas (bundle)** e commitadas (debounce ou confirm explícito) →
  PATCH no `.md` canônico → bridge → CO. Cada bundle vira **backup** (journal /
  snapshot, reusando o mecanismo de draft).
- Otimista na UI (estado já reflete), durável no commit.

### 5. Tutorial como missões + affordances A/B
- **Missões** (2 páginas): objetivos passo-a-passo com detecção de conclusão,
  não-distrativos, primeira-vez. Ex.: ao entrar numa pasta → missão "mova um
  objeto" com **animação** de click-drag.
- NPC entrega tutoriais (canned, sempre) + **Q&A via LLM** (endpoint pluggable/
  env-gated; canned fallback). Backend LLM a decidir (Claude API/Haiku recomendado;
  ou local; ou canned-only no MVP).
- **Affordances A/B**: todo input novo mostra dica (≥ 1ª vez) — barra com `‹ ›`
  alternando variantes; telemetria YG-145 mede qual converte.

## Fatias propostas
1. **Escolha estética** (você) sobre o protótipo → tema(s) default.
2. **Engine real** no instance view: "🌍 Mundo" como nova view (ao lado de mapa/
   timeline/grafo, YG-126), lendo dados reais (InstanceStore) — read+walk+enter.
3. **Edição por manipulação direta**: drag-drop reposiciona/reparent → `coordMap`
   em memória → bundle commit → `.md` frontmatter → bridge/CO. Note CRUD ao pisar.
4. **Backend graph/CRUD CO-compat**: layout no frontmatter, `bundle` endpoint,
   PATCH layout, garantir replicação + write-back (CO-413).
5. **Tutorial-missões + animação + NPC LLM** + GIF Playwright no DoD.
6. **Godot** (opcional/upgrade): cliente Godot consumindo os mesmos contratos.
7. **Multiplayer** (depois): posições no WS de presença (YG-145).

## Decisões (2026-06-14)
- **Estética**: **manter os 5 temas** por enquanto — avaliar pela experiência.
- **Engine do MVP**: **canvas** (sem Godot agora). Godot não está instalado e
  canvas já dá conta (movimento/diagonais/mobile, reusa lobby); fica como upgrade
  com os contratos engine-neutros prontos.
- **NPC**: **Ollama local** + **fallback determinístico `tutorial.md`**. Protótipo
  já roda no determinístico; endpoint Rust com Ollama na fatia de integração.
