## As

A browser client or Godot client

## I Need

Um endpoint unificado para criar e interagir com sessões de qualquer universo, com
WebSocket para stream em tempo real, substituindo as rotas per-game atuais

## So That

Um cliente genérico pode descobrir universos via `GET /api/v1/universos` e jogar
qualquer um deles sem conhecer antecipadamente a rota específica do jogo

## Context

- **Princípios:** §2 (API uniforme), §4 (único ponto de entrada)
- **Depende de:** YG-55 (WasmRuntime), YG-57 (5 universos WASM), YG-58 (Vim)
- **Novo módulo:** `yggdrasil-web/src/universos_routes.rs`
- **Rotas novas:**

  ```
  GET    /api/v1/universos
      → lista todos os universos (id, name, version, max_players, capabilities)

  GET    /api/v1/universos/{id}
      → metadados + schema do state e input (JSON Schema mínimo)

  POST   /api/v1/universos/{id}/sessoes
      body: { config?: object }
      → { session_id, state }

  POST   /api/v1/universos/{id}/sessoes/{sid}/tick
      body: { inputs: [{ key: string, timestamp_ms?: u64 }] }
      → { state, session_ended?, score? }

  DELETE /api/v1/universos/{id}/sessoes/{sid}
      → { final_score } + persiste score + emite SESSION_COMPLETE

  WS     /api/v1/universos/{id}/sessoes/{sid}/ws
      client → server: { key: string }   (um keypress por mensagem)
      server → client: { state }          (estado após cada tick)
  ```

- **WS scope para v1.0:** single-player universos (snake, tetris, invaders, pointset, vim).
  Poker WS multiplayer já existe em `/api/v1/poker/lobbies/{id}/ws` — integração
  ao padrão unificado vem em v1.1.
- **Autenticação:** JWT opcional para single-player (score anônimo descartado se ausente);
  JWT obrigatório se universo declara `capability: wallet-debit`.
- **Rotas legadas permanecem sem alteração:**
  - `GET /api/v1/games/snake/start` → alias para `POST /api/v1/universos/snake/sessoes`
  - `POST /api/v1/games/snake/{id}/input` → alias para `.../tick`
  - Retornam exatamente o mesmo JSON de antes (snapshot test garante)
- **Universo IDs:** `snake`, `tetris`, `invaders`, `pointset`, `poker`, `vim`
  (sem namespace para v1.0; `artelonga/snake` vem pós-release com user uploads)
- **WS implementation:** `axum::extract::ws::WebSocketUpgrade` (já usado em poker).
  Cada conexão WS corre num `tokio::spawn` que lê mensagens e chama `session.tick()`.

## Acceptance

- `GET /api/v1/universos` retorna array com 6 universos, cada um com `id`, `name`,
  `version`, `max_players`, `api_version: 1`.
- `POST /api/v1/universos/snake/sessoes` retorna `{ session_id, state }` em < 50ms.
- `POST /api/v1/universos/snake/sessoes/{id}/tick` com `{ inputs: [{ key: "ArrowRight" }] }`
  retorna estado válido em < 5ms.
- `DELETE /api/v1/universos/snake/sessoes/{id}` persiste score na tabela `scores`.
- WS `snake`: cliente envia `{ key: "l" }` via WS → recebe state atualizado.
- WS fecha limpo quando `state.session_ended == true` (server envia Close frame).
- Rota legada `GET /api/v1/games/snake/start` retorna JSON idêntico ao atual
  (snapshot test: comparar com resposta gravada pré-migration).
- Todas as 6 rotas legadas (snake, tetris, invaders, pointset — sem rotas legadas
  para vim pois é novo) funcionam como aliases.
- `cargo test` passa; WS testado com `axum::test::WebSocketTestClient` in-process.
