## As

A player launching the Godot client to play snake / tetris / invaders / poker / pointset

## I Need

The Godot scenes + GDScript implementations from universos/godot ported into yggdrasil/yggdrasil-godot

## So That

The yggdrasil-godot subproject (currently 9 files — just the HelloUniverso placeholder) gains real game implementations, matching what the Rust route handlers in yggdrasil-web/src/games/ already expose.

## Context

- **Principles:** §6 (folders encapsulate features), §4 (single canonical home for game client)
- **Scope:** Today `yggdrasil-godot/` has 9 files (a HelloUniverso template). `universos/godot/` has 54 files including:

- `scenes/games/{snake, tetris, invaders, pointset, poker}/` (full scenes per game)
- `scripts/games/{snake, tetris, invaders, pointset, poker}/` (GDScript implementations)
- `scenes/lobby/`, `scripts/lobby/` (lobby scene + grid + portals)
- `scenes/main.tscn`, `scripts/autoloads/` (entry point + autoloads)

Port the games + lobby into yggdrasil-godot. Each game's GDScript talks to the Rust HTTP routes in yggdrasil-web (snake_routes.rs, tetris_routes.rs, etc.) — the contract already exists.

## Acceptance

- All 5 games render in yggdrasil-godot client (`make run` or equivalent).
- Each game's GDScript hits the correct yggdrasil-web route — e.g. snake POSTs to `/api/v1/games/snake/start` and ticks via `/api/v1/games/snake/tick`.
- Lobby scene loads + portals to each game.
- E2E smoke test: launch Godot client → play 1 round of each game → score persists to scores table.
- `universos/godot/` no longer referenced anywhere in active code.

## Blast radius

Medium — ~45 files added (scenes + scripts). No backend changes; reuses existing Rust route contract.
