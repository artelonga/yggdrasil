## As

A player stuck num nível do Universo Vim

## I Need

Um sistema de hints contextual que, após 3 tentativas erradas, chama a Claude API
com o estado completo do puzzle e retorna um hint em linguagem natural — sem bloquear
o game loop

## So That

Os hints são adaptativos ao que o player específico tentou (diferente de hints estáticos
por nível), o universo WASM permanece puro (sem API key, sem chamada de rede), e o
host controla custo e rate limiting

## Context

- **Princípios:** §3 (LLM na camada de host, não no game loop), §4 (WASM sem network access)
- **Depende de:** YG-58 (Universo Vim emite `request_hint` via `emit_event`)
- **Referência:** `docs/UNIVERSO-VIM.md §3` — arquitetura do hint system
- **Fluxo:**
  1. WASM emite `emit_event("hint_request", ctx_json)` onde `ctx_json` contém:
     `{ puzzle_id, puzzle_description, buffer_content, cursor, recent_commands[5], attempt_count }`
  2. Host intercepta o evento em `HostState::handle_event()`
  3. Host enfileira chamada assíncrona à Claude API (`claude-sonnet-4-6`)
  4. No próximo tick, `state.hint` contém o texto retornado (ou `null` se ainda processando)
- **Novo módulo:** `yggdrasil-web/src/hint_engine.rs`
  - `HintEngine { client: reqwest::Client, api_key: Option<String> }`
  - `HintEngine::request(ctx) -> impl Future<Output = String>`
  - Prompt: buffer + cursor + últimos 5 comandos + tentativas + idioma do puzzle
  - Rate limit: máx 5 hints/usuário/hora via `DashMap<user_id, (count, window_start)>`
  - Fallback: `ANTHROPIC_API_KEY` ausente → hint estático por nível (hardcoded em `levels.rs`)
  - Model: `claude-sonnet-4-6` (padrão atual da plataforma)
- **Env vars novas:** `ANTHROPIC_API_KEY` (opcional; docs em `DEPLOY.md`)
- **Custo:** hint request = ~500 tokens entrada + ~100 saída ≈ $0.002 por hint.
  Rate limit de 5/hora/usuário = custo máximo por usuário ativo: ~$0.01/hora.
- **Não usar Claude para validar soluções** no v1.0 — validação é puramente
  determinística (`success_fn` compara buffers). Claude só para hints.

## Acceptance

- `ANTHROPIC_API_KEY=sk-...` configurado → `request_hint` retorna texto gerado por Claude.
- `ANTHROPIC_API_KEY` ausente → hint estático fallback por nível, sem erro no log.
- Hint request não bloqueia o tick — tick retorna `{ hint: null }` imediatamente;
  hint chega em tick subsequente (async).
- Rate limit: 6ª solicitação de hint no mesmo usuário na mesma hora retorna o hint
  estático sem chamar a API (verificado por teste que mocka `now()`).
- Contexto enviado ao Claude inclui: texto exato do buffer, posição do cursor,
  últimos 5 comandos, número de tentativas, descrição do puzzle.
- Hint em PT-BR para puzzles com `description_lang: "pt"`.
- `cargo test` passa com mock do `reqwest::Client` (sem chamadas reais à API nos testes).
- `docs/DEPLOY.md` atualizado com instrução de configurar `ANTHROPIC_API_KEY`.

## Blast radius

Low — novo módulo `hint_engine.rs`; modifica `HostState` em `wasm_runtime.rs` para
enfileirar hints. Nenhuma rota existente alterada.
