GIVEN no Mundo real (YG-148) a posição dos objetos é **efêmera** — arrastar não
persiste, e o CO não recebe o layout,

WHEN o drag-drop **reposiciona/reparenta** um objeto → atualiza um `coordMap` em
memória → **commit em lote** → grava `pos{room,x,y}` (e `parent`) no **frontmatter do
`.md`** via `NoteStore` → propaga ao **CO pela bridge (CO-413)**, e a edição de nota ao
pisar (CRUD) também grava no `.md`,

THEN **posição = estado persistido** no `.md` canônico; reabrir o Mundo mantém o layout;
o CO recebe o write-back (federação YG↔CO).

## Design
- `coordMap` em memória durante o arraste; **bundle commit** (lote) pra não escrever a
  cada pixel. Grava `pos{room,x,y}` + `parent` no frontmatter via `NoteStore`.
- **Reparent**: arrastar nota pra outra pasta = mudar `parent` no `.md` + mover na árvore.
- **Write-back CO (CO-413)**: reusar o `co_bridge_producer`/bridge existente — emitir o
  patch de layout/nota ao CO (o CO já consome notas via event-bus; aqui mandamos posição).
- **Nota CRUD ao pisar**: criar/editar/excluir nota grava no `.md` (read já é YG-148).
- Alinhar os nomes com o contrato CO (`pos{room,x,y}`; `room` = caminho de pasta) — é o
  lado YG do mapeamento **pasta=sala ↔ folder-sub-sala** que o CO está construindo.

## Acceptance
- [x] Drag-drop persiste `pos{room,x,y}` no frontmatter `.md` (via `NoteStore`), commit em lote (não por-pixel).
- [x] Reparent (arrastar pra outra pasta) atualiza `parent` no `.md` + move na árvore.
- [x] Nota CRUD (criar/editar/excluir) ao pisar grava no `.md`.
- [x] Write-back ao CO via bridge (CO-413) — o CO recebe o patch de layout/nota.
- [x] e2e Playwright: arrastar objeto → recarregar → posição mantida; reparent → nota na nova pasta.
- [x] `cargo test` + `clippy -D warnings` + `fmt` limpos.

## So that
"Editar manipulando" vira **estado durável** no markdown canônico e **sincroniza com o
CO** — fechando o round-trip de federação que o ecossistema de universos precisa.
