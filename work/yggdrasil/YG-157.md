GIVEN o MundoView unificado (YG-156: loader **lazy** `{rootId, ids, get, roomOf}` +
drag-drop durável + fullscreen) está mergeado, MAS não dá pra **atravessar entre
universos** (vault→vault),

WHEN adicionarmos **portais entre universos** SOBRE o MundoView unificado: no limite
de um vault (ou hub) há uma porta pra outro universo; pisar carrega a instância
destino (lazy, reusa `loader.get`/`ids` do YG-156), spawna o avatar na sala-raiz, com
**stack de universos** pra voltar — **sem regredir** o lazy nem o drag-drop,

THEN o usuário anda entre universos como entre salas (universo ↔ sala-raiz), espelhando
o `universe-as-node` do CO; respeita visibilidade (só universo visível).

## Atenção (mesmo trap do 151→156)
NÃO reescrever o retorno do `loader.js`/`instance-view.js`. Construir os portais SOBRE
o contrato unificado do YG-156 (`{rootId, ids, get, roomOf}` + a API `enter/posOf/drag/
reparent/fullscreen/toggleFullscreen`). Reusar o #87 (fechado) só como referência da
ideia de portal, não do código de loader.

## Acceptance
- [ ] Portal(is) entre universos no MundoView; pisar carrega o universo destino (lazy, reusa YG-156).
- [ ] Stack de universos (voltar); avatar/câmera preservados; só atravessa pra universo visível.
- [ ] **Sem regressão**: lazy `get`/`ids`/`roomOf` + drag-drop durável + fullscreen continuam.
- [ ] e2e: universo A → portal → universo B → andar → voltar.
- [ ] build front + `cargo test` + `clippy`/`fmt` limpos; godot é continue-on-error.
