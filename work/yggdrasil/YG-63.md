## Goal

Cada crate em `universes/` ganha SemVer próprio, CHANGELOG próprio, tag git
própria. Liberta o ritmo de release dos universos do ciclo do core: alterar
`universe-poker` sobe `universe-poker-v0.3.0`, sem bumpar `yggdrasil` 1.0 → 1.1.
A versão real do crate é propagada para o manifest WASM, exposta pelo
`GET /api/v1/universos`, e visível para o cliente.

## Why

- O YG-54 prometeu "after this release the universe crates are open-sourced
  as separate repositories" — o passo intermediário (mesma repo, versão por
  crate) é o trampolim natural e desbloqueia desenvolvimento paralelo já.
- Versionar todos os universos junto com o core obriga bumps cosméticos no
  yggdrasil-web a cada ajuste de UI de um jogo. Não escala quando o catálogo
  crescer (Shandara, chess, sokoban, etc).
- Telemetria (YG-62) já consegue agrupar sessões por `universe_id`; faltava
  agrupar por *versão* do universo (regressão de balanceamento, A/B testing).

## Children

- YG-64 — Padronizar `Cargo.toml` por universe (version + description próprios, fora do workspace.package)
- YG-65 — `CHANGELOG.md` por universe (Keep a Changelog, PT-BR)
- YG-66 — `build-universes.sh` propaga versão do `Cargo.toml` para o manifest WASM
- YG-67 — Convenção de tags git + `docs/UNIVERSE-VERSIONING.md`

## Acceptance

- `cargo metadata --format-version 1` mostra 6 versões distintas em `universes/`.
- `GET /api/v1/universos` retorna `version` real (do Cargo.toml) para cada universo.
- `git tag` aceita o formato `universe-<nome>-v<X.Y.Z>` documentado.
- `cargo test` passa em todo o workspace de universos.
- Documentação `docs/UNIVERSE-VERSIONING.md` explica: quando bumpar (regras de
  compatibilidade entre ABI v1 e o manifest), como taggear, como o build
  pipeline embarca a versão.

## Out of scope

- Extrair universos para repos separados (v2.x).
- Marketplace/registry de universos (v2.x).
- Versionamento do `universe-sdk` (continua semver normal, junto com o crate;
  bump = breaking change da ABI).
