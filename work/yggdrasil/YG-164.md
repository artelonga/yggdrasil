## Por quê
A campanha já tem ledger de apoios (YG-161) + PIX (YG-163) + créditos, mas **não
tem meta nem progresso**. Uma campanha de financiamento precisa mostrar "R$ X de
R$ Y" e quantas pessoas já apoiaram — é o que cria urgência e prova tração. Sem
isso, `/campanha` é uma lista de tiers, não uma campanha.

## Critérios (GIVEN/WHEN/THEN)
- **GIVEN** apoios `confirmado` no ledger (YG-161), **WHEN** abro `/campanha`,
  **THEN** vejo uma **barra de progresso** com: total arrecadado (soma dos
  `valor` dos pledges **confirmados**), a **meta** (R$), o **percentual** e o
  **nº de apoiadores** (confirmados, distintos).
- **GIVEN** a meta é configurável, **WHEN** o operador define
  `YGGDRASIL_CAMPANHA_META` (em reais; default sensato, ex. 0 = "sem meta"),
  **THEN** a barra usa esse valor; sem meta configurada, mostra só total + nº.
- **GIVEN** um endpoint público, **WHEN** chamo `GET /api/v1/campanha/progresso`,
  **THEN** recebo `{ meta, arrecadado, apoiadores, confirmados, percentual }`
  **sem** vazar e-mail/identidade (só agregados).
- **Honestidade:** o "arrecadado" conta **só pledges confirmados** (pagamento
  registrado), não os `pendente` — o número não infla com intenções não pagas.
  (Opcional: expor `pendente` separadamente como "em processamento".)

## Escopo backend
- `PledgeDb`: agregação `progresso()` → soma de `valor` WHERE `status='confirmado'`
  + count distinto de apoiadores. Reusa a tabela `pledges` (YG-161); sem schema novo.
- Rota `GET /api/v1/campanha/progresso` (pública) no `api::campanha`.
- `CampanhaState`/config: `meta` lida de `YGGDRASIL_CAMPANHA_META` (env, opcional).

## Escopo frontend
- `/campanha`: barra de progresso acima dos tiers (meta, arrecadado, %, nº
  apoiadores). Atualiza ao abrir; degrada bem quando `meta=0` (mostra total + nº).
- (Opcional) refletir na `/creditos` o nº de apoiadores.

## Fora de escopo
- Cobrança automática / webhook de PSP (segue manual, YG-163).
- Stretch goals / múltiplas metas (futuro).

## Teste
- Unit (`campanha`): `progresso()` soma só confirmados, conta apoiadores distintos.
- API: `GET /progresso` retorna agregados, nunca e-mail/sub.
- e2e: com N apoios (alguns confirmados via rota admin), `/campanha` mostra a barra
  com o total/percentual corretos.
