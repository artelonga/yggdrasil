GIVEN os universos hoje existem como módulos paralelos (snake/tetris/invaders/poker)
sem uma estrutura formal que descreva variantes (Snake em mapas diferentes,
Tetris com regras diferentes, Poker em modos diferentes),
WHEN crio `yggdrasil_core::universes` com `UniverseNode`/`UniverseRegistry`
modelando universos como grafo recursivo (Root/Variant/Composition) e
expondo via `GET /api/v1/universes`,
THEN o sistema tem uma fundação queryable, documentável e self-contained
que escala para sub-universos arbitrários — espelhando o padrão de
Godot nodes/scenes/instâncias.

## Princípio

**Composição sobre herança**: uma variante (`tetris/sprint-40`) **não estende**
o root (`tetris`) — ela _instancia_ o engine raiz com overrides de parâmetros.
Não há `class TetrisSprint extends Tetris` em lugar algum. O servidor lê
`parameters` da variante e inicia o engine raiz com esses valores.

## Mapa Yggdrasil-hoje → Godot-amanhã

| Hoje (Rust)                        | Amanhã (POC YG-31..YG-35)                                  |
|---|---|
| `UniverseNode { kind: Root }`      | `Tetris.tscn` — scene principal                            |
| `UniverseNode { kind: Variant }`   | `TetrisSprint40.tscn` — sub-scene que `.instance()` + props|
| `UniverseNode { kind: Composition }`| `TetrisDuel.tscn` — instancia 2 × TetrisClassic            |
| `parameters` (JSON)                | `@export` props do Godot                                   |
| Edges parent → child               | `PackedScene.instantiate()` em runtime                     |

A API HTTP `/api/v1/universes` permanece. Quando o Godot POC fechar,
clientes web (canvas) e Godot consomem o mesmo grafo.

## Critérios de aceitação

- [x] `yggdrasil_core::universes::UniverseNode` com `slug`, `parent`,
      `children`, `kind`, `title`, `description`, `parameters: BTreeMap<String, Value>`,
      `api: ApiContract`.
- [x] `UniverseKind::{Root, Variant, Composition}`.
- [x] `ApiContract { start, input, page }` — endpoints + página HTML.
      Variantes apontam para a rota da raiz com `?variant=<slug>`.
- [x] `UniverseRegistry::{register, get, list, roots, children_of, graph}`
      com validação de `DanglingParent` e `AlreadyExists`.
- [x] `default_registry()` semeia 4 roots + 8 variantes:
  - [x] `snake/classic`, `snake/walls`
  - [x] `tetris/classic`, `tetris/sprint-40`
  - [x] `invaders/classic`, `invaders/swarm`
  - [x] `poker/cash-game`, `poker/heads-up`
- [x] `GET /api/v1/universes` — lista plana.
- [x] `GET /api/v1/universes/{*slug}` — wildcard para slugs com `/`.
- [x] `GET /api/v1/universes/graph` — `{nodes, edges}`.
- [x] Anônimos (sem auth) — grafo é informação pública.
- [x] 13 testes de registry + 5 testes de routes.
- [x] `docs/ARQUITETURA-UNIVERSOS.md` ganha seção "Grafo de universos"
      com modelo, contrato HTTP, mapping para Godot, exemplo da árvore,
      heurística de quando promover variante a root.

## Não-objetivos

- **Parametrização real do engine**: hoje variantes são metadados; o
  servidor ainda não lê `?variant=` nas rotas `/api/v1/games/{slug}/start`.
  Próximo task (YG-37+) faz isso.
- **CRUD de variantes**: registry é estático em compile-time. Adicionar
  uma variante dinamicamente (user-generated universes) virá depois.
- **Frontend visualizador do grafo**: hoje só JSON. Renderização tipo
  graphviz/cytoscape é trabalho futuro.
