## As

Um visitante navegando entre o lobby, os universos e o mural do Yggdrasil

## I Need

Uma barra de navegação global, consistente em **todas** as páginas, que sempre
ofereça caminho de volta para o início, para o mapa (lobby), para o catálogo de
universos e para a comunidade — em vez de cada página ter (ou não ter) seu
próprio cabeçalho desconexo.

## So That

A plataforma deixe de parecer um amontoado de páginas soltas e passe a ser um
mapa navegável: cada clique é uma decisão clara dentro de uma malha previsível
de destinos. (Primeira fatia da visão "site como mapa RPG navegável".)

## Context

Origem: **feedback do mural** (`GET /api/v1/feedback`), de *yuri*
(`created_at: 1780352408868`):

> "unificar UI entre paginas, Universos nao tem opcao para voltar, muito
> desconexo por enquanto"

Diagnóstico do estado atual:
- `/` (landing) tem um `header.top` próprio (Início · Comunidade · Mapa · Entrar).
- `/lobby` **não tem cabeçalho nenhum** — sem volta para o início, sem perfil.
- `/universos` só tem um link `← lobby`.
- Universos de jogo (`/universos/*`), `/neuro`, `/feedback` variam.

Padrão de reuso: espelhar `static/feedback.js` — um script auto-injetável, sem
dependências, incluído via `<script>` em cada página. `nav.js` faz o mesmo para
o cabeçalho. JWT em `localStorage["yggdrasil-jwt"]` decide Entrar vs. Perfil.

"Marcar como resolvido" o feedback exige um estado que a tabela `feedback` não
tinha. Esta tarefa adiciona a coluna `resolved` (migração idempotente via
`ALTER TABLE`) e um endpoint admin (mesmo padrão `YGGDRASIL_ADMIN_TOKEN` de
`universos_routes.rs::get_analytics`) para fechar o ciclo: feedback → tarefa →
deploy → resolvido.

## Acceptance

- **GIVEN** qualquer página (lobby, `/universos`, `/universos/*`, `/neuro`,
  `/feedback`)
  **WHEN** a página carrega
  **THEN** aparece a barra global (`static/nav.js`) com links para Início,
  Lobby/Mapa, Universos e Comunidade, marcando o destino atual como ativo.

- **GIVEN** a landing `/`, que já tem `header.top` próprio
  **WHEN** `nav.js` carrega
  **THEN** ele detecta o cabeçalho existente e **não** duplica a barra.

- **GIVEN** um usuário com JWT em `localStorage`
  **WHEN** a barra renderiza
  **THEN** o slot de conta mostra "Perfil/Conta" em vez de "Entrar".

- **GIVEN** a tabela `feedback` já existente em produção (sem a coluna)
  **WHEN** o servidor reinicia e roda a migração
  **THEN** a coluna `resolved` é adicionada idempotentemente (re-boot não falha).

- **GIVEN** um chamador com `Authorization: Bearer <YGGDRASIL_ADMIN_TOKEN>`
  **WHEN** `POST /api/v1/feedback/{id}/resolve`
  **THEN** marca a linha como `resolved = 1` e responde 200; sem token → 401;
  id inexistente → 404.

- **GIVEN** um feedback resolvido
  **WHEN** o mural público `/feedback` lista as mensagens
  **THEN** o item exibe um selo "resolvido" (e-mail/`user_sub` continuam nunca
  expostos).
