GIVEN o login por código (YG-11) usa `game_core::mail::LogMailProvider`,
que apenas imprime o código no stdout do servidor,
WHEN substituo por um `SmtpMailProvider` configurável via env vars,
THEN qualquer pessoa convidada pode logar sem que o admin precise
abrir `flyctl logs` para ler o código.

## Por que está no epic Pôquer

YG-22 quer convidar amigos para jogar (CTA "Convide um amigo"). Sem mail
provider real, esse convite é inútil — o amigo não consegue logar.

## Critérios de aceitação

- [ ] Adicionar `SmtpMailProvider` em `game_core::mail` (ou em
      `yggdrasil-web/src/mail.rs` se o time do `co` preferir não tocar no
      engine; preferência: subir para o engine via PR no `co`).
- [ ] Implementação via crate `lettre` (já usado no co? verificar antes).
- [ ] Config via env vars:
  - [ ] `YGGDRASIL_SMTP_HOST` (obrigatório)
  - [ ] `YGGDRASIL_SMTP_PORT` (default 587)
  - [ ] `YGGDRASIL_SMTP_USER`
  - [ ] `YGGDRASIL_SMTP_PASSWORD` (via fly secrets)
  - [ ] `YGGDRASIL_SMTP_FROM` (default "Yggdrasil <noreply@artelonga.com.br>")
- [ ] Se nenhuma var SMTP estiver setada → continua usando `LogMailProvider`
      (modo dev). Log claro: `WARN smtp not configured — emails go to stdout`.
- [ ] Documentar em `docs/DEPLOY.md` como configurar (ex.: SendGrid, AWS SES, Mailtrap).
- [ ] Teste de integração com Mailtrap ou similar (sandbox SMTP).
- [ ] Atualizar `fly.toml` com placeholder das env vars (sem valores).

## Não-objetivos

- HTML templates de email (texto puro basta — código + expiração).
- DKIM/SPF/DMARC (responsabilidade do provedor + DNS do `artelonga.com.br`).
- Reply-to handling.
