GIVEN o frontend de pôquer (YG-23/25) consulta `/api/v1/poker/lobbies/{id}`
a cada 2s — gera tráfego inútil em mesas dormentes e latência
desnecessária em mesas ativas,
WHEN substituo o polling por um WebSocket que pusha eventos
(`hand_started`, `actor_changed`, `player_acted`, `hand_ended`),
THEN o cliente recebe atualizações em <100ms e o servidor evita N
requisições/seg por usuário ocioso.

## Critérios de aceitação

- [ ] Adicionar feature `axum::extract::ws` (já está no axum 0.8).
- [ ] Endpoint `GET /api/v1/poker/lobbies/{id}/stream` (Upgrade: websocket, JWT como query param `?token=…` ou Sec-WebSocket-Protocol).
- [ ] Mensagens JSON tagged: `{"type": "hand_started", ...}`, etc.
- [ ] Servidor mantém `tokio::sync::broadcast::Sender<LobbyEvent>` por lobby.
- [ ] Cliente:
  - [ ] Estabelece WS no enter, fecha no leave.
  - [ ] Reconnect automático com backoff 1s / 2s / 5s / 10s.
  - [ ] Fallback para polling se WS falhar 3x seguidas.
- [ ] Remover `setInterval(refreshLobby, 2000)`.
- [ ] Logs claros no servidor: connect/disconnect com user_id + lobby_id.

## Não-objetivos

- Substituir polling em Snake/Tetris/Invaders (single-player, não precisa).
- Server-Sent Events como alternativa (uma trilha basta).
