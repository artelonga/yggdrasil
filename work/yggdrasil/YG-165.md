## Por quê
Hoje confirmar um apoio (YG-161/163) só dá por `curl` com `YGGDRASIL_ADMIN_TOKEN`.
Para **operar** uma campanha viva o operador precisa **ver** os apoios que chegam
(tier, valor, nome, recado, status, quando) e **confirmar** quando o PIX cai —
numa tela, não no terminal. Sem isso a campanha está deployada mas não operável.

## Critérios (GIVEN/WHEN/THEN)
- **GIVEN** o operador tem o `YGGDRASIL_ADMIN_TOKEN`, **WHEN** abre `/campanha/admin`
  e informa o token, **THEN** vê a **lista de pledges** (mais recentes primeiro):
  tier, valor, nome, e-mail, recado, `status` (pendente/confirmado), data.
- **GIVEN** um pledge `pendente`, **WHEN** clica **"Confirmar pagamento"**,
  **THEN** chama `POST /campanha/pledges/{id}/confirmar` (YG-161) → vira
  `confirmado`, credita as sementes do tier, e a linha atualiza (✓).
- **GIVEN** sem token / token errado, **THEN** a lista não carrega (401) e a UI
  pede o token — nada de dado exposto sem auth.
- **GIVEN** a rota de listagem é nova, **WHEN** `GET /api/v1/campanha/pledges`
  com `Authorization: Bearer <admin>`, **THEN** retorna os pledges **completos**
  (inclui e-mail/user_sub — é a visão do operador, gated por admin token);
  401 sem token. **Esta é a única rota que expõe e-mail**, e só para admin.

## Escopo backend
- `PledgeDb::list_all()` (admin) → todos os pledges com todos os campos.
- Rota `GET /api/v1/campanha/pledges` no `api::campanha`, gated por `admin_token`
  (mesmo padrão de `confirmar_pledge`). Reusa `confirmar` para a ação.

## Escopo frontend
- Página `/campanha/admin` (servida via rota, fora da nav pública): campo de
  token (guardado em memória/sessionStorage), tabela de pledges, botão Confirmar
  por linha. PT-BR. Sem libs pesadas (vanilla).

## Fora de escopo
- Gestão de usuários/roles (o admin token único basta para a fase de campanha).
- Edição/estorno de pledges; relatórios/export (futuro).

## Teste
- API: `GET /pledges` 401 sem token; 200 com admin token (traz e-mail só aqui).
- e2e: com admin token, a tela lista pledges e "Confirmar" move pendente→confirmado
  (reflete via API); sem token, não lista.

## Notas de segurança
`GET /pledges` é a **única** superfície que devolve e-mail/identidade, e é
admin-only. As rotas públicas (`/creditos`, `/progresso`) continuam sem PII.
