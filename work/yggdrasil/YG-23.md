GIVEN os endpoints de auth (YG-11) e o adapter single-player de Pôquer
(YG-9) existem, mas pôquer ainda 404'a no lobby (ver bugfix do deploy
2026-05-12),
WHEN crio o modelo `PokerLobby` com 6 assentos, rotas auth-gated de
sit/stand/list, e frontend que checa JWT no localStorage,
THEN o universo Pôquer ganha o esqueleto multiplayer — usuário loga,
escolhe mesa, senta, e vê o bot fillin' quando está sozinho.

> **Status retroativo.** Entregue durante a sessão de teste do deploy em
> 2026-05-12, antes do epic YG-22 ser formalizado. Este arquivo existe
> para evitar que `co-auto` reimplemente o mesmo trabalho.

## Critérios de aceitação

- [x] `yggdrasil-core/src/games/poker_lobby.rs`:
  - [x] `PokerLobby` com `seats: Vec<SeatOccupant>` (6 assentos).
  - [x] `SeatOccupant::{Empty, Human { user_id, sat_at }, Bot}` serializável.
  - [x] `sit(seat, user_id)`, `stand(user_id)` com erros tipados PT-BR.
  - [x] Regra de bot: 0 humanos → 0 bots; 1 humano → 1 bot; 2+ humanos → 0 bots.
  - [x] 9 testes unitários cobrem entrada/saída + re-balanceamento.
- [x] `yggdrasil-web/src/games/poker_routes.rs`:
  - [x] `GET /api/v1/poker/lobbies` — listar (auth).
  - [x] `GET /api/v1/poker/lobbies/{id}` — estado (auth).
  - [x] `POST /api/v1/poker/lobbies/{id}/sit` body `{seat}` (auth).
  - [x] `POST /api/v1/poker/lobbies/{id}/stand` (auth).
  - [x] Provisiona "Mesa Carvalho" e "Mesa Olmo" no boot.
- [x] `yggdrasil-web/static/games/poker.{html,js}`:
  - [x] CTA de login quando `localStorage.getItem('yggdrasil-jwt')` ausente.
  - [x] Selector de mesa com contagem de humanos/bots/vagas.
  - [x] Tabela com 6 assentos clicáveis; CTA "Convide um amigo" quando há bot na mesa.
  - [x] Polling 2s para refletir entradas/saídas de outros jogadores.
- [x] `yggdrasil-web/static/login.{html,js}` — flow email → código → JWT.

## Notas

Sem dealing/betting nesta sub-tarefa — só o seating. Cartas, blinds e
pots vêm em YG-25. CTA "EM CONSTRUÇÃO" no header e seção "Mecânica de
partida virá na próxima entrega" são proibidas de remover até YG-25
fechar.
