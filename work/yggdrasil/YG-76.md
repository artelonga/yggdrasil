## As

Qualquer cliente do editor (web ou Godot, host-neutral)

## I Need

Um conjunto de endpoints REST para criar, listar, carregar, salvar e editar
instâncias de universo, com edição **granular** via `EditOp` validada no servidor

## So That

O contrato REST é a fronteira estável que qualquer front-end consome — o cliente
fica fino e o servidor valida invariantes num único ponto

## Context

Ler `docs/architecture/editor.md` (§ "REST API"). Novo
`yggdrasil-web/src/api/instances.rs`, um `instances_router` `.merge`d em `main.rs`
espelhando o padrão de `api/universes.rs` (handler `async fn(State, Path/Json) ->
Json`, `State<InstancesState>` com `Arc<InstanceStore>` + `jwt_secret`). Auth via
`sub` do JWT (mesmo padrão de `auth.rs`/rotas existentes).

### Rotas (subset desta story — anexos ficam em YG-77, play em YG-78)

| Método | Rota | Função |
|---|---|---|
| POST | `/api/v1/instances` | criar (`?template=` semeia — handler aceita o param mas o seeding completo é YG-79) |
| GET | `/api/v1/instances` | listar do caller (`?published=true` → feed público) |
| GET | `/api/v1/instances/{id}` | carregar JSON |
| PUT | `/api/v1/instances/{id}` | salvar instância inteira |
| PATCH | `/api/v1/instances/{id}` | aplicar `EditOp` |
| DELETE | `/api/v1/instances/{id}` | apagar |

### EditOp

Enum serde `#[serde(tag="op", rename_all="snake_case")]` (assinatura no doc):
`PlaceBlock`, `MoveBlock`, `DeleteBlock`, `EditLayer`, `AddLayer`, `AddConnection`,
`DeleteConnection`, `AttachContent`. O handler carrega a instância, aplica o op,
valida, persiste via `InstanceStore::save`, bumpa `updated_at`.

### Validações (ponto único)

- `Connection` com `from`/`to` inexistente → 422.
- `Cell` fora dos limites do `GridSpec` → 422.
- `opacity` fora de `0.0..=1.0` → 422.
- `block_id` duplicado na layer → 409.
- Owner mismatch (instância não pertence ao `sub`) → 403.
- Instância inexistente → 404.

## Acceptance

- `yggdrasil-web/src/api/instances.rs` implementa os 6 handlers acima + a lógica
  de aplicação/validação de `EditOp`.
- `instances_router` `.merge`d em `main.rs` (sem tocar routers de arcade).
- Auth: todas as rotas exigem JWT válido; ownership checado em get/put/patch/delete
  (exceto `?published=true` que é público read-only).
- POST cria via `InstanceStore::create` e retorna 201 + a instância (com `id`,
  `owner=sub`, timestamps).
- PATCH aplica cada variante de `EditOp` corretamente e persiste; as 6 validações
  acima retornam os status corretos.
- Testes de integração (axum `oneshot` como nas rotas existentes): create → patch
  PlaceBlock → get confirma o bloco; patch AddConnection com endpoint inválido →
  422; delete → get 404; owner B não acessa instância de owner A → 403.
- OpenAPI (`openapi.rs`) atualizado com as novas rotas.
- `cargo test --workspace`, `clippy -D warnings`, `fmt --check` limpos.
- CHANGELOG `[Unreleased]` atualizado; bump minor.

## Blast radius

Médio — novo router aditivo `.merge`d em `main.rs`. Nenhum router de arcade,
WASM ou registry tocado. Depende de `InstanceStore` (YG-75).
