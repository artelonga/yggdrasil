GIVEN o `LexiconPack` (YG-155) existe como contrato Rust em
`yggdrasil-core/src/comunicacao/pack.rs`, MAS os únicos packs (`music_pack()`,
`language_pack()`) estão **hardcoded em Rust** — autorar uma nova linguagem hoje
exige editar código e **recompilar**, o que contradiz a visão "adicionar uma
linguagem = soltar um pack",

WHEN definirmos um **formato de pacote em arquivo** (YAML, com corpo Markdown
opcional por entrada) que **desserializa para `LexiconPack`** via serde, e um
carregador `pack::load_dir(path) -> Vec<LexiconPack>` que lê packs de um diretório
(`data/packs/<id>.yaml`), com helpers de notação (ex.: `note: "C4"` resolve
`freqs` via `note_freq`, `chord: ["C4","E4","G4"]`) p/ que o autor escreva notas
por NOME e não Hz cru,

THEN um autor cria uma nova linguagem jogável **dropando um arquivo** — sem tocar
em Rust nem recompilar — e o pacote-exemplo prova o formato ponta-a-ponta
(arquivo → parse → mesmo JSON servido por `/api/v1/comunicacao/packs/{id}`).

## Design
- **Schema de arquivo** (`PackFile`): superset serde-friendly do `LexiconPack`,
  com `audio` autorável por atalhos:
  - `audio: { note: "C4", waveform: triangle, duration_ms: 500 }` → `Synth` 1 voz.
  - `audio: { chord: ["C4","E4","G4"], waveform: sawtooth, duration_ms: 900 }` → `Synth` N vozes.
  - `audio: { sequence: [{ chord: [...], duration_ms: 480 }, ...] }` → `Sequence`.
  - `audio: { speech: { text, ipa?, lang } }` → `Speech`.
  - `freqs`/Hz cru ainda aceitos (escape hatch p/ microtonal).
- **Loader** em `pack.rs` (ou `pack_file.rs` novo): `load_file(path)`,
  `load_dir(dir)`; valida `kind`/`notation`; erro claro por arquivo inválido
  (não derruba os outros packs).
- **Fonte de packs**: `seed_packs()` continua embutido (fallback memory-light);
  packs de arquivo **adicionam-se** aos seed (env `YGGDRASIL_PACKS_DIR`,
  default `data/packs`). Sem regressão da rota atual.
- **Pack-exemplo de arquivo**: `data/packs/exemplo.yaml` — pequeno (≤8 entradas),
  cobre `note`, `chord`, `sequence` e/ou `speech`, com `pos` abstrata.

## Acceptance
- [ ] Tipo `PackFile` (serde, YAML) que desserializa para `LexiconPack`, com atalhos `note`/`chord`/`sequence`/`speech` resolvendo notas por nome via `note_freq`.
- [ ] `load_file(path)` e `load_dir(dir)` em `yggdrasil-core/src/comunicacao/`; arquivo inválido gera erro identificável e **não** aborta os demais.
- [ ] Rota `/api/v1/comunicacao/packs` e `/packs/{id}` passam a incluir packs de arquivo (`YGGDRASIL_PACKS_DIR`, default `data/packs`) **além** dos seed embutidos.
- [ ] `data/packs/exemplo.yaml` (≤8 entradas) cobre `note` + `chord` + (`sequence` ou `speech`), carrega e serve com o MESMO shape JSON dos seed.
- [ ] Teste: parse do `exemplo.yaml` → `LexiconPack` round-trips para o JSON servido (atalho `note:"A4"` ⇒ `freqs:[440.0]`).
- [ ] Doc: `docs/architecture/lexicon-pack-contract.md` ganha seção "Formato de autoria" (atalhos + exemplo). Sem editar fontes existentes (criar a seção em arquivo novo se necessário, ou anexar — ver constraint da sessão).
- [ ] `cargo test` + `clippy -D warnings` + `fmt` limpos.

## So that
Adicionar uma linguagem (idioma, música, domínio) vira **autoria de conteúdo**, não
mudança de código — o pré-requisito p/ packs comunitários (Iorubá, Hebraico, neuro)
e p/ a ponte CO→pack (YG-169).

## Não no escopo
- UI de edição de packs no browser (autoria é arquivo por enquanto).
- Validação semântica profunda de teoria musical / linguística.
- A ponte CO-universe → pack (YG-169, consome este loader).
