GIVEN o `LexiconPack` já carrega `entropy_stats { symbols, bits_per_symbol }`
(YG-155) e o pack é caminhável (YG-171), MAS **não há loop de jogo**: bits são só
um número estático, o jogador não **ganha** nem **gasta** nada, e "bits = score"
da visão ÑE'Ẽ não existe como mecânica,

WHEN definirmos o **loop de bits/score** — o jogador **ganha bits** ao
*descobrir* (primeiro contato com uma entrada: ouvir + ver) e ao *identificar
corretamente* (mini-quiz: ouço o som / vejo a glosa → escolho o termo), creditando
`bits_per_symbol` da entrada (de `entropy_stats` ou `log2(symbols)`), e **gasta
bits** para *revelar* uma glosa/relação escondida (pista paga) — com o saldo
persistido por usuário,

THEN ÑE'Ẽ tem economia: aprender uma linguagem **rende bits** proporcionais à sua
informação (Shannon), e bits compram pistas — fechando o laço descobrir → testar →
gastar que torna o léxico um **jogo**, não um navegador de palavras.

## Design
- **Modelo de score** (core, ex. `comunicacao/score.rs`):
  `BitsLedger { user, total_bits, discovered: Set<entry_id>, identified: Set }`.
  Ganho por **descoberta** (1ª vez): `floor(bits_per_symbol)` (ou um mínimo de 1).
  Ganho por **identificação correta**: bônus (ex.: `2 * bits_per_symbol`),
  decrescente com tentativas (anti-brute-force). Reusa o sinal de acerto do
  `review.rs` (SRS-lite) quando aplicável.
- **Gasto**: revelar glosa oculta custa `ceil(bits_per_symbol)`; saldo nunca < 0.
- **Persistência**: por usuário (JWT `sub`), em disco junto de
  `YGGDRASIL_COMUNICACAO_DIR` (mesma política das salas; idempotente por entrada).
- **Rotas** (back): `GET /api/v1/comunicacao/score`,
  `POST /api/v1/comunicacao/score/descobrir` ({pack, term}),
  `POST /api/v1/comunicacao/score/identificar` ({pack, term, correct}),
  `POST /api/v1/comunicacao/score/revelar` ({pack, term}) → debita ou 402.
- **Anti-cheat leve**: descoberta credita 1×/entrada (Set); identificação valida
  no servidor (termo correto não vem do cliente como verdade).
- **UI**: HUD de bits no Mundo (YG-171); botão "revelar (−N bits)"; mini-quiz ao
  pisar (A/B: quiz imediato vs sob demanda — telemetria YG-145).

## Acceptance
- [ ] `BitsLedger` por usuário: descoberta credita `bits_per_symbol` 1×/entrada (idempotente); identificação correta credita bônus decrescente por tentativa.
- [ ] Gasto: `revelar` debita `ceil(bits_per_symbol)`; saldo insuficiente ⇒ HTTP 402/erro claro, saldo nunca negativo.
- [ ] `bits_per_symbol` vem de `entropy_stats` quando presente; senão `log2(n_símbolos_do_pack)` (reusa `EntropyStats::uniform`).
- [ ] Rotas `score` / `score/descobrir` / `score/identificar` / `score/revelar` com auth por `sub`; identificação validada **no servidor**.
- [ ] Persistência por usuário em `YGGDRASIL_COMUNICACAO_DIR` (escrita atômica temp+rename, como salas).
- [ ] HUD de bits no Mundo de pack (YG-171) + botão "revelar (−N)" + mini-quiz; A/B do timing do quiz com telemetria.
- [ ] Testes core do ledger (crédito idempotente, débito, piso 0) + e2e: descobrir → +bits, revelar → −bits, revelar sem saldo → bloqueado.
- [ ] `cargo test` + `clippy -D warnings` + `fmt` + Playwright verdes.

## So that
"bits = score" deixa de ser slogan: a quantidade de informação (Shannon) de uma
linguagem **é** a recompensa por aprendê-la, e bits têm utilidade (pistas) — a
espinha de gamificação sobre a qual quests e progressão são construídas.

## Não no escopo
- Quests/missões completas e árvore de progressão (próxima tarefa).
- Economia entre usuários / leaderboard multiplayer (futuro, YG-145 substrato).
- Balanceamento fino dos números (começar simples; iterar por telemetria).
