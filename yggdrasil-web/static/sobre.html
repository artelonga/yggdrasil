YGGDRASIL

Conectando ideias. Construindo universos.

Cada jogo é um universo. Cada universo é um nó num grafo recursivo — pode ser composto, instanciado, parametrizado. Composição sobre herança, do código ao gameplay.

O QUE É

Yggdrasil é uma plataforma viva de criação, organização e conexão de universos digitais. Cada universo é um espaço onde elementos crescem como raízes, galhos e folhas — e podem virar mundos jogáveis.

A primeira release pública traz quatro universos clássicos reinterpretados, um lobby 2D navegável, autenticação unificada entre as propriedades artelonga, e um modelo de moeda interna chamado sementes. Toda a arquitetura é desenhada para escalar: novos universos plugam no grafo existente sem reescrever nada.

SEMENTES

Moeda interna do Yggdrasil. Você ganha ao vencer mãos de pôquer, ganhar torneios, completar desafios. Pode gastar para entrar em mesas privadas, personalizar avatares e — eventualmente — criar seu próprio universo.

Saldos são por usuário, persistidos em wallet própria, auditados em log transacional.

IDENTIDADE UNIFICADA

Uma conta serve todas as propriedades artelonga: co.artelonga.com.br, quilomboaraucaria.org, Yggdrasil e futuras. Login via Google ou email-código — em ambos os casos, o servidor do CO é a autoridade. Yggdrasil recebe sua sessão via JWT ES256 verificado por JWKS, sem segredo compartilhado.

GRAFO DE UNIVERSOS

Cada universo é um nó no grafo público em /api/v1/universes. Há três tipos:

  • Root — define o engine (Snake, Tetris, etc).
  • Variant — instancia o engine raiz com overrides de parâmetros (snake/walls, tetris/sprint-40).
  • Composition — combina múltiplos universos (em desenvolvimento — tetris/duel).

Variantes não estendem o root — instanciam. Composição sobre herança, conceito tomado emprestado do Godot Engine. A árvore é forward-compat com a POC Godot em curso: o mesmo grafo vira uma árvore de .tscn scenes quando o substrato migrar.

ARQUITETURA

Backend em Rust + Axum, reaproveitando o engine 2D do projeto irmão co/game-core. Persistência em SQLite (via rusqlite), deploy em Fly.io com volume montado em /data. Frontend é HTML5 <canvas> + JavaScript vanilla — sem framework pesado.

Cada universo respeita um contrato de 3 camadas:

  • Domínio — estado, regras, transições (yggdrasil-core/games/<slug>.rs).
  • HTTP — endpoints Axum, auth, persistência (yggdrasil-web/games/<slug>_routes.rs).
  • Frontend — UI canvas/DOM (static/universos/<slug>.{html,js}).

Universos não importam outros universos. O lobby é o único despachador. Detalhes em docs/ARQUITETURA-UNIVERSOS.md no repositório.

POKER MULTIPLAYER

Texas Hold'em real entre humanos, com bot de fallback quando solo. Três mesas: Mesa Carvalho (6 seats, cash game), Mesa Olmo (6 seats, cash game), Heads-Up Carvalho (2 seats, duelo). Buy-in: 1.000 sementes.

Cartas, apostas, pots e showdown são autoritativos no servidor. Estado sobrevive a deploys via snapshot em SQLite. Mãos memoráveis podem ser salvas em /favoritos e revistas a qualquer momento.

API PÚBLICA

Documentação completa da API HTTP em docs/API.md no repositório. Endpoints principais:

  • GET /api/v1/universes — grafo de universos
  • GET /api/v1/scores/top — top 3 por jogo
  • GET /api/v1/users/{username} — perfil público
  • POST /api/v1/auth/google/start — login (delegado ao CO)
