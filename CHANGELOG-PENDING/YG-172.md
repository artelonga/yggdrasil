## YG-172 — Comprovante de PIX (apoiador anexa; operador vê "aguardando" vs "enviado")

O PIX é pago fora de banda; faltava o time saber que um apoio **já foi pago**. O
apoiador agora pode sinalizar o pagamento e (opcional) anexar o comprovante.

### Added
- **`POST /api/v1/campanha/pledges/{id}/comprovante`** (público pelo id; multipart
  `nota` texto e/ou `arquivo` imagem/PDF, ≤5 MB): marca o apoio como
  "comprovante enviado" (carimbo). Vazio → 400, id inexistente → 404, tipo
  inválido → 415, grande demais → 413.
- **`GET /api/v1/campanha/pledges/{id}/comprovante/arquivo`** — baixa o arquivo,
  **admin-gated** (só o operador vê o comprovante).
- **Landing**: na tela do PIX, form opcional "Já pagou? Envie o comprovante"
  (arquivo + nota). O modal agora rola (`max-height/overflow`) — cabe em telas
  pequenas.
- **Admin** (`/campanha/admin`): coluna **Comprovante** — "aguardando" vs
  "📎 enviado" (+ nota) + botão "ver arquivo" (download autenticado via blob).
- Config `YGGDRASIL_COMPROVANTES_DIR` (default `data/comprovantes`; volume).

### Tests
- API: enviar (nota/arquivo/vazio/404/415), baixar (401 sem token, 200 com),
  estado na lista admin. Migração idempotente. e2e `comprovante` (API + landing).

### Segurança
O **arquivo** só sai pela rota admin. A rota de **envio** é pública (por id do
próprio apoio) — nenhuma PII nova nas rotas públicas.
