## YG-104 — reparar crates WASM v1.0 (drift do universe-sdk) + lint Godot; CI bloqueante de novo

### Fixed
- **Crates WASM v1.0** (`universe-{snake,tetris,invaders,pointset,poker}`) voltaram a
  compilar para `wasm32-unknown-unknown` contra a API atual do `universe-sdk`. Cada crate
  agora implementa o trait `Universe` (`create`/`tick`/`manifest`) e usa os novos helpers
  do SDK no lugar dos símbolos removidos (`get_random`/`kv_load`/`kv_store`).
- **`universe-sdk`**: novos wrappers seguros sobre os host imports — `random_seed()`,
  `kv_load(key) -> Option<Vec<u8>>`, `kv_store(key, &[u8])`. Os host imports passaram a ser
  gated por `target_arch = "wasm32"` (com `#[link(wasm_import_module = "env")]`) e ganharam
  stubs nativos, para que testes nativos das crates linkem sem um host WASM real.
- **ABI host ↔ SDK**: o `universe_exports!` agora também exporta
  `process(input_ptr, input_len) -> i64` — o export que o runtime (`wasm_runtime.rs`) de fato
  chama — respaldado por uma sessão implícita por instância. Assinaturas de `kv_set`/`request_hint`
  alinhadas ao host (retorno void). Os testes de integração que carregam os blobs reais
  (`*_10_ticks_return_valid_json`, `poker_kv_state_survives_session_reconstruction`) passam.

### CI
- Removido o band-aid do **WASM** no `.github/workflows/ci.yml`: restaurados
  `cargo install wasm-opt --locked` + `bash scripts/build-universes.sh` (no lugar do skip por
  stub) — o build WASM real volta a gatear (validado no CI, 7 testes `wasm_runtime` carregam
  os blobs reais).
- O job **`godot`** permanece `continue-on-error: true`, mas a razão muda de band-aid para
  **decisão de escopo**: o spike YG-35 (`docs/adr/YG-35-godot-vs-canvas.md`) **descopou** os
  jogos 2D Godot (poker/snake/tetris) — o canvas é o cliente de produção, Godot só para o
  `anatomy3d`. Os erros de parse de GDScript nesses jogos descopados não valem conserto; o lint
  roda e reporta, sem gatear. (Item 3 do YG-104 vira moot pelo descope, não "reparado".)
