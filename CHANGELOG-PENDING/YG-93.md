## YG-93 — Producer de eventos p/ a federated bus do CO (Fase P-A)

Adiciona o producer que publica notas do Yggdrasil ao hub do CO (CO-384),
seguindo o ADR `docs/architecture/event-driven-sync.md` (emit/one-way push).

- **Hook de emissão** (`yggdrasil-web/src/api/instances.rs`): cada
  `NoteStore::save`/`delete` via API publica exatamente um `NoteWritten`
  (`instance`, `slug`, `kind`, `title`, `body`, `updated_at`) num canal
  `tokio::sync::broadcast` — mesmo padrão do poker. `NoteStore` segue puro.
- **Novo `yggdrasil-web/src/co_bridge_producer.rs`**: envelope `FederatedEvent`
  (`entry.{created,updated,deleted}`, `universe_key=yggdrasil`,
  `path=notes/<slug>.md`, `payload={title,body,updated_at}`, `hop_count`
  loop-guard); `event_log` append-only com `last_delivered_event_id`
  (cold-start NULL → log inteiro; warm-reconnect → a partir do último ACK; mesmo
  code path); **cold-start seed** enumerando `InstanceStore::list_all` +
  `NoteStore::list` p/ sintetizar `entry.created` das notas da Fase 0; reconnect
  com backoff exponencial 1s→30s.
- **Gate de config**: sem `YGG_CO_BRIDGE_URL` + `YGG_CO_BRIDGE_TOKEN` o producer
  é **no-op** — não sobe task, não toca rede, não afeta o boot nem os testes.
  Spawn de fundo em `main.rs` espelha `universos_routes::spawn_cleanup_job`.
- Nova dependência: `tokio-tungstenite` (rustls, sem openssl) para o dial WS.

**Escopo desta entrega:** build + unit-test da lógica pura (envelope, event_log,
offset de `last_delivered`, backoff, seed de cold-start, gate de env, hook de
emissão). O **E2E ponta-a-ponta pende CO-384** — o hub `/api/v1/events/bridge`
ainda não existe, então o dial WS real fica documentado/stubado até lá. Aplicar
eventos inbound (CO → Yggdrasil) é Fase P-B (v3.1), fora de escopo.
